## Abstract

This proposal establishes Zeron's versioning model before and after the 1.0 release. Before 1.0,
artifacts use `0.X.Y` with prerelease identifiers as needed. Starting with the 1.0 release
candidate, public release names use whole-number major-series names such as “Zeron 1,” while
artifacts retain full, patchable semantic versions.

## Motivation

Release planning needs stable, sortable version identifiers that distinguish feature releases,
patches, and prerelease builds. The project also wants simple public names for stable major series
without losing the ability to identify patch-level artifact releases.

## Goals

- Define artifact versions for pre-1.0 feature releases, patches, and prereleases.
- Define how public whole-number release names relate to post-1.0 artifact versions.
- Preserve distinct patch versions in package metadata, archives, and release artifacts.

## Non-goals

- Changing the current Maven or release artifact version as part of accepting this policy.
- Defining source, binary, standard-library, or API-index compatibility guarantees beyond the
  existing version policies.
- Replacing the independently versioned standard-library API or API-index schema.

## Proposal

Use the following canonical artifact version rules:

### Before 1.0

- Use `0.X.Y`, where `X` advances for each feature release and `Y` advances for a patch release
  within that release line.
- Feature releases advance `X` and reset `Y` to zero; patch releases advance `Y`.
- Use SemVer prerelease identifiers with an increasing numeric suffix, such as
  `0.3.0-alpha.1`, `0.3.0-beta.1`, and `0.3.0-rc.1`.
- A final release omits the prerelease suffix, such as `0.3.0`. Version ordering follows SemVer:
  alpha precedes beta, beta precedes release candidate, and prereleases precede the final version.
- Pre-1.0 releases do not promise the compatibility guarantees associated with a stable 1.0 API.

### From the 1.0 release candidate onward

- The first release candidate is `1.0.0-rc.1`; the corresponding final release is `1.0.0`.
- Public “Zeron N” names identify the artifact major-version series `N.x.y`; for example, “Zeron 1”
  includes artifacts such as `1.0.0` and `1.1.0`, while preserving distinct patch artifacts such as
  `1.0.1`.
- After 1.0, use SemVer: increment the major version for incompatible changes, the minor version
  for backward-compatible feature releases, and the patch version for backward-compatible fixes.
- Use the same numbered prerelease identifiers for alpha, beta, and release-candidate builds.

Do not infer the standard-library API version or binary API-index schema version from the compiler
artifact version; those remain independently versioned compatibility contracts.

## Compatibility and impact

This policy standardizes future version names but does not rename or rewrite existing releases,
tags, or artifacts. Apply the canonical format on the next version change. Release scripts and
manifests should consume the project version defined in the Maven build metadata rather than
independently constructing version strings.

## Alternatives

- Use integer-only artifact versions after 1.0 — rejected because it cannot distinguish patch
  releases cleanly in dependency metadata.
- Keep `0.X.Y` artifact versions after 1.0 — technically workable, but does not provide the desired
  public major-series names or conventional stable-version compatibility signaling.
- Use whole-number names as aliases for full artifact versions — accepted as the public naming layer,
  while artifacts retain their full SemVer identifiers.

## Implementation and validation

When adopting the policy in build metadata, verify that the project version is defined in one place,
release archive names and checksum sidecars use the canonical artifact version, prerelease ordering
is correct, and public release labels map to the artifact major series. Preserve independent API
index and standard-library version behavior. The Maven project version remains the source of truth
for the current artifact version.

## Decision

Accepted 2026-10-13. Use `0.X.Y` and numbered SemVer prereleases before 1.0. Beginning with
`1.0.0-rc.1`, use public whole-number major-series names while preserving full patchable SemVer
artifact versions. Release targets are tracked independently of this policy decision.
