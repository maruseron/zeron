# ZEP-0018: Final-Version Release Targets in ZEP Tracker

## Abstract

This proposal standardizes release references in the ZEP tracker: target the final version of a
release bundle, not an alpha, beta, or release-candidate artifact version.

## Motivation

A release bundle may have multiple prerelease artifacts before publication. Tracking each proposal
against a prerelease identifier would make the intended bundle appear to change as it moves from
alpha to beta to release candidate. The tracker should identify the final bundle consistently while
artifact metadata continues to distinguish prerelease builds.

## Goals

- Keep one stable release reference for proposals targeting a bundle across its prerelease cycle.
- Preserve the distinction between a release bundle target and a particular artifact build.
- Keep SemVer prerelease identifiers governed by the artifact versioning policy in ZEP-0012.

## Non-goals

- Changing artifact version ordering or prerelease naming.
- Requiring a release to have alpha, beta, or release-candidate builds.
- Changing the meanings of Candidate, Planned, or Shipped release states.

## Proposal

Use the final version of a release bundle as its tracker reference, including for Candidate and
Planned entries. For example, proposals intended for the bundle published as `0.3.0` use `0.3.0`
as their release reference even if implementation is validated in an artifact named
`0.3.0-rc.1`. The prerelease identifier belongs to the artifact version, not the ZEP bundle target.

## Compatibility and impact

This changes only release-reference notation in the central ZEP tracker. It does not rename
artifacts, alter SemVer behavior, or change release-state transitions. Existing published
references remain the final published versions.

## Alternatives

- Track prerelease artifact versions directly — rejected because the target reference would need
  repeated updates as the same bundle advances through prerelease builds.
- Track only informal release names — rejected because final artifact versions provide a precise,
  stable bundle identifier.

## Implementation and validation

Document the convention in the release-tracking process and use final bundle versions in tracker
references. Verify that prerelease artifact examples remain in the artifact-versioning policy and
that shipped tracker entries continue to identify the published version.

## Decision

Accepted 2026-10-17. ZEP tracker release references identify the final bundle version, while
prerelease suffixes identify individual artifacts produced during that bundle's development.
