## Abstract

This proposal adds a Zeron language server using the Language Server Protocol (LSP), initially
providing diagnostics, completion, hover, and definition navigation. It keeps protocol handling
outside reusable compiler APIs and defines project and open-document analysis needed for reliable
results.

## Motivation

Editors can provide syntax highlighting without understanding Zeron's project configuration,
imports, types, contract evidence, or diagnostics. A language server could expose compiler-backed
navigation and assistance to multiple editors through a standard protocol.

[ZEP-0009](./ZEP-0009.md) establishes a public, protocol-independent member discovery API and
explicitly leaves cursor-aware analysis and editor integration to a future layer. An LSP should
reuse appropriate semantic services without coupling the discovery model or compiler core to LSP
types. It will also need to analyze unsaved and sometimes incomplete source, which is beyond
type-level member discovery alone.

## Goals

- Provide diagnostics, completion, hover, and definition navigation as the initial capability set.
- Reuse compiler-owned parsing, resolution, project, and public discovery services where suitable.
- Specify open-document overlays, source versioning, diagnostics, cancellation, and recovery from
  incomplete or invalid source.
- Support project configuration, imports, compiled libraries, and source provenance consistently
  with command-line builds.
- Keep the server protocol adapter separate from reusable language and compiler APIs.

## Non-goals

- Requiring a particular editor or shipping a VS Code-only semantic implementation.
- Replacing the command-line compiler or the public member discovery API.
- Adding a debugger protocol, build-system dependency resolver, or remote development service as
  part of the initial LSP scope.
- Guaranteeing advanced refactoring or complete semantic recovery before the initial feature set is
  agreed.

## Proposal

Implement diagnostics, completion, hover, and definition navigation first. Defer references,
rename, formatting, code actions, and refactoring to later proposals or revisions. For each
initial capability, define behavior for ambiguous names, extensions and their import requirements,
contract-provided members, generic bounds, compiled libraries without source, and incomplete
expressions.

Ship a stdio `zeron lsp` command in the existing distribution. Keep LSP protocol types and
dependencies in the adapter layer; do not add them to the compiler's public semantic model.
Initially support one project per server process, loading the same manifest, source roots,
standard-library mode, and library/classpath inputs as a build.

Maintain versioned open-document overlays in memory and combine them with the project's on-disk
sources for each analysis snapshot. Never write overlays or editor analysis outputs into the build
output directory. Cancel obsolete work where possible and, in all cases, discard results whose
document versions are stale. Publish diagnostics only for open documents, tagged with their current
versions; clear their published diagnostics when documents close. A regular CLI build remains the
way to report project diagnostics for closed files.

Initially advertise LSP 3.17 with UTF-16 positions, keeping coordinate conversion at the adapter
boundary and following ZEP-0009's UTF-16 provenance convention. Reuse the parser's existing
recovery and diagnostics, then add targeted editor-facing recovery for common incomplete cursor
contexts; do not make the entire parser broadly tolerant as an LSP prerequisite.

Use a protocol-independent project/document analysis layer for cursor-sensitive scope and symbol
queries. `PublicMemberCatalog` remains the type-level discovery API, not the cursor-query API.
Compiled libraries can provide semantic information from their metadata; definition navigation is
available only when source provenance exists. Keep server caches isolated from CLI and incremental
compilation caches for this MVP.

## Compatibility and impact

The LSP is an additional integration surface and should not require LSP protocol dependencies in
the compiler's public semantic model. Its packaging, supported protocol version, launcher behavior,
and compatibility policy must be decided. Reusing the ZEP-0009 API may reveal missing semantic
queries; any additions should be justified as protocol-independent capabilities rather than
editor-specific leakage.

## Alternatives

- **Editor-specific integrations** — may provide a tighter single-editor experience, but duplicate
  semantic work and limit reuse across tools.
- **Syntax-only editor support** — lightweight and robust for incomplete text, but cannot offer
  reliable type-aware navigation or diagnostics.
- **Wait for the public discovery API to cover editor needs** — avoids premature server design, but
  type-level discovery intentionally excludes cursor-sensitive scope and incomplete-source
  analysis.
- **Put LSP types directly in compiler APIs** — may simplify a prototype, but couples the language
  model and future consumers to one transport protocol.

## Implementation and validation

The MVP is implemented as `zeron lsp [--manifest <file>]`, with one manifest-backed project per
stdio server. It provides diagnostics, completion, hover, and definition using project snapshots,
resolver reference data, and `PublicMemberCatalog`; protocol types remain in the adapter. Open
documents are versioned in-memory overlays, incremental UTF-16 changes are applied against the
current text, diagnostics are published only for open documents and cleared on close, and stale
analysis results are discarded. Analysis does not write generated output. When a newer document
revision arrives, the previous analysis future and task are canceled: queued obsolete work is
skipped, and running analysis is interrupted and checks cancellation during source discovery and
processing, and before and after semantic resolution. Resolver internals do not yet check
interruption, so an active resolution is allowed to reach its phase boundary before cancellation is
observed; revision checks still prevent stale results from being published.

Focused workspace and generic-client protocol tests cover overlay diagnostics, cancellation
checkpoints, no output writes, completion and navigation, open-document-only publication, stale
versions, incremental ranged changes, diagnostic clearing, and shutdown. Existing parser recovery
is used; broad parser tolerance and additional cursor-specific recovery remain out of scope until
concrete editor contexts require them. Multi-project workspaces remain deferred.

## Resolved implementation decisions

- **Incomplete source:** reuse existing parser recovery first; add targeted cursor-context recovery
  for useful completion and analysis without requiring a broad parser rewrite.
- **Packaging and transport:** provide `zeron lsp` in the existing distribution and communicate
  over stdio. Isolate the protocol adapter and its dependency from compiler semantic APIs.
- **Project discovery:** one project per server process, using its build manifest and configuration.
  Multi-root workspace support is deferred.
- **Diagnostics:** analyze the full project snapshot, including open-document overlays, but publish
  diagnostics only for open documents. Tag diagnostics with document versions and clear them on
  close; use CLI builds for diagnostics on closed files.
- **Semantic queries:** keep cursor-sensitive queries in an editor-independent analysis layer.
  Extend the public discovery API only for generally useful, protocol-independent queries; do not
  make `PublicMemberCatalog` itself cursor-aware.
- **Caches:** use server-owned caches/snapshots only. Sharing caches with CLI or incremental
  compilation is deferred until cache identity and isolation guarantees are established.

## Decision

Accepted 2026-10-18. Build an LSP adapter over protocol-independent compiler and project services.
The initial capability set is diagnostics, completion, hover, and definition navigation, with
versioned open-document overlays and cancellation of obsolete analysis. Keep protocol types out of
the compiler API. Defer references, rename, formatting, code actions, and refactoring. Packaging,
workspace scope, diagnostic publication, position encoding, cache isolation, and incomplete-source
recovery are resolved as specified above.
