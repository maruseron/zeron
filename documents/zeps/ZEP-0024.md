## Abstract

This proposal defines a discoverable `zeron.math` extension API for common operations over Zeron's
built-in numeric types, with explicit behavior for overflow, rounding, floating-point special
values, and domain errors.

## Motivation

Zeron provides `Int` and `Float` plus basic operators, but does not yet define a dedicated math
library. A standard module can provide common functions without requiring applications to rely on
host-specific Java APIs. The public contract must specify numeric edge cases rather than merely
wrapping platform functions.

## Goals

- Identify a small, useful set of mathematical functions for `Int` and `Float`.
- Define overflow, rounding, precision, special-value, and domain-error behavior.
- Keep runtime math functions distinct from generic numeric admissibility and operator constraints.

## Non-goals

- Arbitrary-precision arithmetic, complex numbers, units, or generic numeric operators.
- A `Char` primitive or networking API; these are explored separately.
- Promising cross-platform bit-for-bit floating-point results unless explicitly specified.

## Proposal

Add public extension families in the `zeron.math` package. Extension methods provide common names
for receiver-distinct numeric types without introducing ordinary function overloading.

- `Int`, `Long`, and `Float` expose `abs()`, `min(other)`, `max(other)`, and
  `clamp(min, max)`.
- `Float` exposes `sqrt()`, `pow(exponent)`, `exp()`, `ln()`, `log10()`, `sin()`, `cos()`,
  `tan()`, `asin()`, `acos()`, `atan()`, and `atan2(x)`. Trigonometric inputs and results use
  radians; `atan2(x)` computes the angle for the receiver as `y`.
- `Float` exposes `floor()`, `ceil()`, and `trunc()` returning `Float`, plus `round()` returning
  `Long`. Rounding follows `java.lang.Math`: `round` selects the nearest integer with ties toward
  positive infinity, maps NaN to zero, and saturates infinities and out-of-range finite values at
  the `Long` limits.
- The package exposes `PI`, `TAU`, and `E` as `Float` constants; `TAU` is the nearest representable
  `Float` value to `2 * PI`.
- `Float.NaN` remains available, and `Float.POSITIVE_INFINITY` and `Float.NEGATIVE_INFINITY` are
  added as named special-value constants.

Integer `abs` retains the existing JVM two's-complement wraparound behavior: the minimum representable
`Int` or `Long` remains negative because its positive magnitude is not representable. This module
does not add checked integer arithmetic.

Floating-point operations follow `java.lang.Math` and JVM IEEE-754 behavior. Domain and range
outcomes are represented by NaN or infinities rather than `Option` values or raised effects. This
includes operations such as square root of a negative finite value and logarithm of zero. Floating
`min`, `max`, and `clamp` follow the corresponding `java.lang.Math` behavior for NaN, infinities,
and signed zero. Calling `clamp` with a lower bound greater than its upper bound throws
`java.lang.IllegalArgumentException`.

The API does not promise bit-for-bit identical transcendental results across JVM implementations;
it follows the accuracy and special-case guarantees of `java.lang.Math`. It introduces no
closed-set `numeric` admissibility constraint; that remains deferred in
[ZEP-0010](./ZEP-0010.md). Generic arithmetic behavior is provided separately by the algebraic
contracts in [ZEP-0036](./ZEP-0036.md).

## Compatibility and impact

This adds standard-library extensions and constants to compiled-library metadata. It should not
change existing operator semantics or generic well-formedness. Existing `Float.NaN` behavior is
retained; the infinity constants and new operations extend the public surface. Platform-backed
implementations must preserve the documented source-level behavior.

## Alternatives

- Use Java interop or external libraries — avoids standardizing an API, but reduces portability and
  discoverability.
- Add only a minimal set of built-ins — may be smaller, but risks scattering mathematical
  operations across the language rather than a coherent module.
- Defer a dedicated module — avoids premature semantics until concrete application needs arise.

## Implementation and validation

Test integer minimum-value absolute values, clamp bounds, rounding ties and range limits, infinities,
NaN, signed zero, and invalid floating-point domains. Verify extension discovery, compiled-library
metadata, and behavior on supported JVM platforms.
