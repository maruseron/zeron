# ZEP-0027: VS Code Language Client for Zeron

## Abstract

Extend the existing VS Code language-support extension with a language client that launches the
Zeron language server and exposes its existing editor features for `.zn` files.

## Motivation

The current VS Code extension associates `.zn` files with the Zeron grammar and provides basic
editor behavior, but it does not start the LSP server. Users therefore cannot access the server's
compiler-backed diagnostics, completion, hover, or definition navigation from VS Code without
manually configuring a client.

ZEP-0021 provides a stdio-based `zeron lsp` command. A small VS Code client can connect the editor to
that server without duplicating language semantics or adding VS Code dependencies to the compiler's
semantic APIs.

## Goals

- Integrate the existing `zeron lsp` server with the current VS Code extension.
- Expose the capabilities already provided by the server, including diagnostics, completion, hover,
  and definition navigation.
- Preserve the existing `.zn` language association, TextMate grammar, and editor configuration.
- Make server startup failures visible and actionable to the user.
- Keep the extension as a protocol client rather than implementing compiler semantics itself.

## Non-goals

- Adding new LSP capabilities or changing server semantics defined by ZEP-0021.
- Implementing language features independently in the VS Code extension.
- Bundling a compiler, JDK, or runtime with the extension as part of the initial scope.
- Supporting other editors or replacing the generic LSP server.

## Proposal

Add a VS Code language client to `editors/vscode` and launch the existing `zeron lsp` process over
stdio for a single-project workspace. By default, launch `zeron` from `PATH` and append the fixed
`lsp` argument. Provide a `zeron.server.path` setting to override the executable path; arbitrary
server arguments are not configurable.

The client should use the workspace root as the process working directory and rely on the server's
existing manifest discovery. Support one Zeron project per VS Code workspace; multi-root workspaces
are deferred. The extension requires a separately installed Zeron distribution and does not bundle
or download a compiler or Java runtime. The installed Zeron launcher remains responsible for the
supported Java runtime requirements.

The extension should retain its existing syntax grammar and language configuration. LSP features
augment those editor facilities rather than replacing them. The client should tolerate a missing or
unlaunchable server by reporting a clear setup error without disabling syntax highlighting.

## Compatibility and impact

This changes the VS Code extension's runtime behavior and introduces a language-client dependency,
but does not change Zeron source syntax, generated code, standard-library APIs, or LSP protocol
semantics. Users need an installed Zeron distribution with the `lsp` command and its supported Java
runtime. Version the extension independently from the compiler. Document Zeron 0.3.0 as the initial
minimum supported server version, and test the extension against that minimum and the current Zeron
release.

The extension's supported VS Code version must satisfy the language-client dependency's requirements.
Process launch and shutdown behavior must work with the platform-specific Zeron launchers, including
Windows.

## Alternatives

- **Keep the extension grammar-only and require manual client configuration** — avoids maintaining a
  language client, but leaves VS Code users to configure the existing server themselves.
- **Bundle or download the compiler/server with the extension** — could simplify initial setup, but
  adds platform-specific packaging, update, and runtime responsibilities.
- **Implement editor features directly in the extension** — avoids a server process, but duplicates
  compiler behavior and ties semantic support to VS Code.
- **Add a VS Code-specific server implementation** — could optimize for one editor, but conflicts
  with ZEP-0021's protocol-independent server design.

## Implementation and validation

Implement the client in the existing `editors/vscode` extension, keeping the server process and
protocol adapter in the compiler distribution. Validate activation for `.zn` documents, successful
stdio initialization against `zeron lsp`, delivery of diagnostics and existing language features,
clear reporting when the executable cannot be started, and clean client shutdown. Exercise process
launch on Windows and at least one Unix-like platform, and verify that the existing grammar-only
behavior still works when the server is unavailable. Test against Zeron 0.3.0 and the current
distribution; publish the extension on an independent version cadence.

## Decision

Accepted on 2026-10-18. Use `zeron` from `PATH` by default with a `zeron.server.path` executable
override and a fixed `lsp` argument; initially support one project per workspace; require a separately
installed Zeron distribution; and version the extension independently with Zeron 0.3.0 as its
documented initial minimum supported server version. Multi-root support and bundled or downloaded
server/runtime packaging are deferred.
