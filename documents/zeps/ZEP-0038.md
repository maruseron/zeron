## Abstract

This proposal adds a `zeron version` CLI command that reports the version of the invoked Zeron
distribution without requiring a project or source file.

## Motivation

Users and support tools need a direct way to identify which Zeron release is installed, especially
when comparing behavior across machines or reporting bugs. The version is currently discoverable
through release metadata or package filenames, neither of which is convenient or reliable for an
ordinary CLI user.

## Goals

- Add a simple `zeron version` command.
- Make it usable from any working directory, without a project manifest.
- Report the version of the running Zeron compiler/CLI distribution.
- Keep the output stable and suitable for copying into bug reports or scripts.

## Non-goals

- Reporting Java runtime, operating system, or environment diagnostics.
- Inspecting project or standard-library API compatibility.
- Checking for updates or contacting a remote service.
- Adding a general machine-readable diagnostics command.

## Proposal

Recognize `version` as a top-level CLI command:

```text
zeron version
```

The command prints the version of the invoked Zeron distribution to standard output and exits
successfully. It runs independently of the current directory and does not load a project manifest,
compile source, or modify files.

The output should be concise and stable, for example:

```text
zeron 0.5.0
```

The CLI supports both `zeron version` and the conventional `zeron --version` alias; both produce
the same output. The version is the exact Maven project version, including any prerelease suffix.
The build embeds this value in generated metadata used by both packaged and Maven development
builds, rather than maintaining a separate hard-coded CLI version. If launched from raw classes
without version metadata, the command reports `zeron development`. The command reports the product
version, not the standard-library API or API-index schema version.

Extra arguments are rejected using the CLI's normal invalid-argument behavior. The exact first
argument `version` and the `--version` option are reserved for this command; source paths with
extensions are unaffected, and a bare path named `version` can be explicitly qualified.

## Compatibility and impact

This adds a top-level CLI command and does not change compilation or project-command behavior. A
bare relative path exactly named `version` becomes reserved as the first CLI argument; callers can
disambiguate such an input with an explicitly qualified path such as `./version`. Ordinary source
filenames with extensions are unaffected. The command should be documented in CLI help and
release/installation guidance where appropriate. No language, standard-library, compiled-library,
or runtime compatibility changes are expected.

## Alternatives

- **Require users to inspect package metadata** — avoids a CLI change, but depends on knowing how a
  particular installation was packaged.
- **Add only a `--version` flag** — familiar to many command-line users, but inconsistent with the
  existing subcommand-oriented CLI; it may still be added as an alias later.
- **Print version information as part of `zeron help`** — useful context, but does not provide the
  direct, scriptable command requested.

## Implementation and validation

The CLI parser and dispatch path support both version invocations and reject extra arguments. Maven
generates the version metadata from the project version for development and packaged builds; raw
classes without that metadata report `development`. Tests verify exact output, aliases, argument
rejection, source-path compatibility, and agreement with the POM. The release packaging script
smoke-tests the version reported by its shaded JAR.
