## Abstract

Add declaration documentation comments to Zeron. Documentation attached to declarations should be
available to language tooling, including LSP hover, and preserved in compiled-library metadata so
clients can inspect documentation without the original source.

## Motivation

Zeron currently recognizes line and block comments as comments, but does not associate their content
with declarations. As a result, source authors cannot write declaration documentation that follows
symbols through language tooling or compiled libraries. LSP hover can show a declaration signature
and inferred type, but not author-provided explanations.

Documentation comments would let authors explain public APIs next to their declarations and make
those explanations available to both source and separately compiled library users.

## Goals

- Introduce a recognizable documentation-comment syntax without changing ordinary comments.
- Attach documentation to declarations using predictable source-location rules.
- Display associated documentation in LSP hover using Markdown.
- Preserve public declaration documentation in the compiled API index for separately compiled
  clients.
- Keep ordinary comments and documentation comments distinct in parsing and formatting.

## Non-goals

- A complete documentation-site generator or package browser.
- A required documentation format, tag vocabulary, or lint policy.
- Evaluating code examples embedded in documentation.
- Defining documentation inheritance or automatic propagation through overrides and witnesses.
- Changing the semantics or visibility of declarations.

## Proposal

Use consecutive `///` line comments immediately preceding a declaration as documentation comments:

```zeron
/// Returns the exact rational value represented by the decimal literal.
/// The conversion does not pass through `Float`.
public fn parseExact(value: String): Rational;
```

Consecutive documentation lines form one Markdown document, with the comment marker and one
optional following space removed from each line. Existing `//` and `/* ... */` comments remain
ordinary comments and do not attach to declarations.

The initial feature supports `///` line comments only; block documentation syntax is deferred.

Documentation comments attach to the next declaration in the same syntactic scope when no blank
line or intervening non-documentation comment separates them. A blank line, ordinary comment, or
end of scope ends the pending documentation. Documentation comments between modifiers and a
declaration should be diagnosed or treated consistently; the initial design should require them
to precede the declaration's modifiers.

Documentation may be attached to declarations with user-facing names, including functions, classes,
contracts, type aliases, namespaces, properties, class and contract members, extension members,
product components, and sum cases. Documentation on local bindings and parameters is not included
in the initial scope. A documentation group must precede all declaration modifiers; comments placed
between modifiers and the declaration are not attached.

When LSP hover resolves a declaration with documentation, it should present the existing signature
or type information together with the Markdown documentation. Symbols without documentation retain
the existing hover behavior. Hover should use the documentation associated with the resolved
declaration, including when the reference is imported from a compiled library.

Documentation for public declarations is stored in the versioned Zeron API index. Private
declaration documentation remains available to source-based tooling but is omitted from compiled
metadata. Documentation text is metadata only: it does not affect resolution, generated bytecode,
or runtime behavior.

The source formatter should preserve documentation comments, their attachment, and Markdown text.
Formatting ordinary comments remains governed by the existing formatter behavior.

## Compatibility and impact

Existing comment syntax and programs remain valid. The scanner, parser, declaration model, LSP
symbol/hover model, API index, and source formatter are affected. Public documentation is included
in API-index schema 7, the schema revision already planned for the 0.6.0 candidate's data-class
metadata. Documentation is consolidated into that unreleased schema revision; it does not require
a second schema increment. Preview indexes created before this consolidation must be regenerated.

The standard library and bundled source can adopt documentation incrementally. Documentation
comments are optional and their absence does not affect API availability.

## Alternatives

- **Use ordinary `//` comments as documentation when adjacent to a declaration** — rejected because
  it gives existing implementation comments a new semantic role and makes attachment less explicit.
- **Use block-style `/** ... */` comments only** — not selected for the initial design because
  line-oriented comments are simpler to write and format. A block form could be considered later.
- **Keep documentation in source only and omit it from library metadata** — rejected because
  separately compiled clients and bundled-library tooling would lose the documentation.
- **Add documentation through external sidecar files** — rejected as the primary mechanism because
  keeping source declarations and documentation synchronized would be harder.

## Implementation and validation

The implementation distinguishes `///` comments during scanning, attaches contiguous groups to
declarations and supported members, preserves them in formatting, and appends Markdown to source
and compiled-library hover. Public documentation is serialized as documentation records in API
index schema 7; private documentation remains source-only. Tests cover scanner and formatter
behavior, source hover, public/private metadata, and documented declaration/member exports.

## Open questions

None. The initial syntax is `///`; private documentation is retained for source tooling and
omitted from compiled metadata.

## Decision

Accepted 2026-10-22. The initial implementation uses `///` line comments, retains private
documentation only in source tooling, and stores public documentation in compiled API-index
metadata. This metadata is part of the already-planned schema 7 candidate revision. Block
documentation syntax is deferred.
