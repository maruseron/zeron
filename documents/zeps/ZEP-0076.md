# ZEP-0076: Delegating Witness Implementations

## Abstract

Add an opt-in `delegating witness` declaration modifier that synthesizes witness methods by
forwarding compatible, non-mutating instance requirements to public instance methods already
declared by the witness target class. Witness evidence remains explicit, and static requirements
remain explicitly implemented.

## Motivation

A class may already provide the behavior required by a contract without declaring nominal
conformance. Its package can then provide a witness, but must currently repeat trivial forwarding
methods for each matching operation. This duplication is especially noisy for generic capability
contracts with both instance operations and static constructors.

## Goals

- Make delegation an explicit property of the witness declaration.
- Reuse compatible public instance methods on a target class to satisfy abstract contract methods.
- Preserve explicit witness methods as the authoritative implementation when supplied.
- Preserve explicit witness declarations as the source of evidence and coherence.
- Keep static requirements and unmatched instance requirements visible and explicit.

## Non-goals

- Inferring witnesses from class methods without a witness declaration.
- Adding static methods to ordinary classes or delegating static requirements.
- Delegating to fields, properties, extensions, Java members, or methods on a different receiver.
- Replacing contract defaults or changing nominal class conformance.
- General wrapper-method delegation syntax.

## Proposal

Write `delegating` immediately before `witness`:

```zeron
delegating witness<T: Numeric<T>> Numeric<Vector2<T>> for Vector2<T> {
    static fn fromInteger(value: Integer): Vector2<T> {
        // Static requirements remain explicit.
    }
}
```

For a delegating witness, the compiler considers each abstract, non-static, non-mutating contract
requirement not already implemented explicitly. If the target is a declared Zeron class with a
public non-mutating method of the same name and a compatible signature after substituting witness
and contract type parameters, the compiler synthesizes a witness helper that calls that method on
the target receiver.

Explicit witness methods take precedence over delegation, including when an explicit method is
invalid; the compiler reports the explicit method's error rather than silently falling back to a
target method. Contract default methods continue to use their default implementation unless
explicitly overridden by the witness. A requirement without a compatible target method remains
missing and produces the existing diagnostic and quick fix. Static requirements are never
delegated and must be implemented explicitly.

Only public instance methods declared directly on the target class are candidates. Matching uses
the existing method-signature compatibility rules, including generic method parameters, effects,
variadics, and return assignability. Delegation does not establish nominal `is` conformance and
does not synthesize evidence in the absence of the witness declaration.

## Compatibility and impact

This adds source syntax but does not change the meaning of existing witness declarations. The
`delegating` modifier is recognized contextually before `witness`, so it need not become a reserved
identifier elsewhere. Delegated methods are materialized as ordinary witness implementations
during resolution; compiled witness metadata therefore continues to describe the effective
implementations without requiring a new runtime representation.

## Alternatives

- A `delegate;` body directive — rejected because delegation is a property of the witness as a
  whole and a declaration modifier communicates it more clearly.
- Implicitly use any matching class method for every witness — rejected because accidental
  same-named methods would silently change evidence behavior.
- Require users to write explicit forwarding methods — rejected because it retains the
  duplication this proposal addresses.
- Delegate static requirements through companion types — deferred because ordinary Zeron classes
  do not currently provide class-scoped static methods.

## Implementation and validation

- Parse and retain the contextual `delegating` modifier on witness declarations.
- Synthesize forwarding helper functions for eligible contract methods before witness validation.
- Exercise generic and non-generic targets, explicit overrides, default methods, missing methods,
  static requirements, and compiled-library metadata.
- Validate that delegated calls compile and dispatch to the target's public method.

## Open questions

None. The initial scope is deliberately limited to direct public instance methods of nominal Zeron
classes.

## Decision

Accepted on 2026-10-22. The declaration-level modifier keeps delegation opt-in and readable.
Explicit implementations override generated delegation, while static and unmatched requirements
remain explicit. This preserves witness coherence and avoids defining static delegation before
Zeron has class-scoped static functions.
