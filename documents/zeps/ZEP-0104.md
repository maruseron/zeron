## Abstract

This proposal is the first slice of the former existential-types exploration. It introduces two
distinct forms:

- **star projections** `F<*>`, a read-only view equivalent to `F<out Any?>`;
- **anonymous existentials** `F<: B + C>`, an unknown type argument with upper bounds and optional
  markers, including `reified`.

It also introduces implicit packing and **exact type-bound pattern matching** built on the shared
runtime descriptor from [ZEP-0015](./ZEP-0015.md).

The split replaces the earlier `F<?>` and `F<? : markers>` spellings. `?` remains only the postfix
nullability marker, so `Box<*>` cannot be confused with `Box<Int?>`, and `Box<*>?` is unambiguously
a nullable star view.

It deliberately does not introduce stored existentials, result-position existentials, variance,
a named existential binder, scoped opening, or runtime contract-bound tests. The initial slice is
intended to give 0.7.0 a user-visible reification feature: code can recover the concrete type of a
hidden or reified value and branch on it soundly.

**Implementation status (2026-11-10).** The revised slice is implemented in the compiler:

- `F<*>` parses as the existing `F<out Any?>` projection, and `Array<*>` is rejected.
- `<: bounds + markers>` parses only as a direct type argument of a declared function, method, or
  contract-method parameter. Nested arguments, variables, fields, results, receivers, arrays,
  lambda parameters, and function-type parameters are rejected.
- Each anonymous existential lowers to a hidden type parameter appended after the declaration's
  explicit type parameters. It is inferred from arguments, forwards its bounds and contract
  evidence, and never consumes an explicit call-site type argument.
- `reified` hidden parameters and reified type parameters carry ZEP-0015 descriptors. Exact applied
  type tests compare the source and target descriptors; a null source is false. Non-reified or
  otherwise non-describable sources keep the existing static/erased test path.
- Contract methods and class implementations may use anonymous existentials, and the lowered
  signature remains compatible across the contract boundary.

Deliberately outside this slice: stored and result-position existentials, scoped opening, variance,
rank-2/function-type existentials, runtime contract-bound tests, general skolemized local escape
analysis, and descriptor-allocation measurements. The formatter currently renders a universal
projection as `out Any?`; rendering it as `*` is optional and not required by this revision.

## Revision note

## Motivation

ZEP-0015 provides runtime identity for applied source types. Effects are one consumer. Type-bound
matching is the other, and it has a more direct user-facing shape:

- a generic operation receives a value whose concrete type is captured at the call site;
- the callee can test whether that type is `Box<Int>`, `Box<String>`, or another closed type;
- on a successful test, existing flow typing gives the branch a useful static type.

Without reification, generic arguments are erased and such a test is either unsound or limited to
the erased JVM class.

Two smaller needs sit next to it:

- a function that accepts a container of *any* argument should be able to say so without declaring
  a type parameter it never uses: `fn count(box: Box<*>): Int`;
- a function that needs an unknown argument with capabilities, or with a runtime descriptor, needs
  a bounded anonymous existential: `fn describe(box: Box<: Render + reified>): String`.

`Box<*>` is exactly the existing universal projected view `Box<out Any?>`. It is deliberately not
a binder: it has no descriptor, no evidence, and no identity. `Box<: B + C>` is the new binder: it
has an unknown exact type argument bounded by `B` and `C`, can carry a descriptor when marked
`reified`, and can carry bound evidence where the bound requires it.

This slice also validates the descriptor design against a second consumer before generic effect
payloads depend on it.

## Goals

- Define star views `F<*>` as read-only projection sugar for `F<out Any?>`.
- Define anonymous existentials `F<: B + C + markers>` in declared callable parameter positions,
  with implicit packing.
- Use the ZEP-0015 descriptor for reified anonymous existentials and reified type parameters.
- Support exact type-bound tests against closed applied types.
- Lower successful tests to the existing cast and flow-refinement machinery.
- Keep contract evidence separate from type identity.
- Introduce no source-level binder form, so ZEP-0105 and ZEP-0109 can decide naming and opening
  with full information.

## Non-goals

- A type-argument wildcard spelled `?`; postfix `?` remains nullability only.
- A named existential binder in type position (`<let T> T`) or an `any`-style contract type.
- Stored existentials, heterogeneous collections, and holder ABI; see [ZEP-0106](./ZEP-0106.md).
- General existential result positions, scoped opening, variance, and pointwise subtyping; see
  [ZEP-0105](./ZEP-0105.md).
- Rank-2 polymorphism and polymorphic function types; see [ZEP-0109](./ZEP-0109.md).
- Anonymous existentials in lambda or function-type parameter positions. Those require rank-2
  invocation semantics and belong to [ZEP-0109](./ZEP-0109.md).
- Subtype, interface, or ancestor matching of non-effect types: no proposal owns it yet
  ([ZEP-0107](./ZEP-0107.md) covers effects only).
- Contract-bound runtime matching; see [ZEP-0108](./ZEP-0108.md).
- General reflection or runtime member discovery.
- Changing `AnyField`, `Model`, or property references.
- Replacing projections from [ZEP-0052](./ZEP-0052.md).
- `Array<*>`; arrays continue to reject projections.

## Proposal

### Surface forms

Each existential need has one tool, and no tool is a binder inside a type:

| Need | Form |
|------|------|
| A value of some conformant of a contract | the contract as the type: `fn f(p: Render)` |
| Name a type and relate positions | ordinary type parameter: `fn f<T: Render>(a: T, b: T): T` |
| Reify a named type | `fn f<T: Render + reified>(p: T)` |
| Read a container whose argument is unknown | star view: `F<*>` |
| Same, but with a known upper bound | named projection: `F<out B>` |
| Hide a type argument with bounds or markers | anonymous existential: `F<: B + C>` |
| Same, with a runtime descriptor | `F<: B + C + reified>` |
| Unbounded anonymous existential with a descriptor | `F<: reified>` |

`F<_>` remains the existing erased/HKT placeholder and never denotes a capture-carrying
existential.

### Star views

`F<*>` is read-only sugar for `F<out Any?>`.

- It has no binder and no fresh type. It is the existing universal projection.
- It is accepted wherever the equivalent `F<out Any?>` projection is accepted. It is not restricted
  to parameter positions, because it adds no new type-system capability.
- It may appear nested wherever projections are accepted, for example `List<Box<*>>`, because that
  is just `List<Box<out Any?>>`.
- It supports the existing projection rules for member access, assignment, and capture. It carries
  no runtime descriptor and no bound evidence.
- An exact type test on a star view is a compile-time error: there is no hidden argument identity
  to test. Use `F<: reified>` when an exact test is required.
- `Array<*>` is rejected because arrays reject projections. This is a deliberate first-version
  restriction, not a holder limitation.

The formatter may render the universal `out Any?` projection as `*`; the two spellings are
semantically identical.

### Anonymous existential grammar and positions

`<:` starts an anonymous bound list at the beginning of a direct type argument:

```zeron
Box<: Render>
Box<: Render + Numeric>
Box<: reified>
Box<: nullable + reified>
Map<: KeyBound, : ValueBound>
```

A leading `:` is required for each anonymous existential argument; there is no closing marker.
The bound list reuses the existing generic-bound grammar: contracts joined with `+`, plus the
admissibility markers `nullable`, `mut`, `reified`, and the effect markers where applicable.
`F<:>` with no bound or marker is rejected.

Anonymous existentials are accepted only as **direct type arguments of the outermost applied type
of a parameter type** of a declared function, method, or contract method. They are rejected:

- in variable and field types;
- in result types;
- nested inside another type argument (`List<Box<: B>>` requires a holder per element);
- in receiver positions;
- in lambda and function-type parameter positions, which are rank-2 and belong to
  [ZEP-0109](./ZEP-0109.md);
- in arrays.

Each `<: ...>` is an independent hidden type. `fn f(a: Box<: B>, b: Box<: C>)` does not relate the
two arguments; use a type parameter for that.

A postfix `?` after the closing `>` continues to mean a nullable outer type: `Box<: reified>?` is a
nullable Box with a reified anonymous argument. There is no ambiguity with the old wildcard form
because `?` never appears at the start of a type argument.

### Relation to projections

Zeron's projections (`F<out B>`, `F<in B>`, ZEP-0052) are declaration-directed bounded views of an
unknown argument. This slice does not change them.

The three forms have distinct jobs:

| Form | Binder? | Bound | Descriptor/evidence |
|------|---------|-------|---------------------|
| `F<*>` | no | universal `out Any?` | none |
| `F<out B>` | no | named upper view | none |
| `F<: B + C>` | yes | anonymous upper bounds | only with `reified` or evidence-bearing bounds |

`F<: B>` is not a synonym for `F<out B>`. The former introduces an unknown exact argument that can
be reified, captured, forwarded, and constrained by multiple bounds; the latter is a read-only view
of an argument whose identity is still fixed by the surrounding type. A single-bound anonymous
existential is still useful because it carries the binder and can carry a descriptor.

Member access on an anonymous existential follows the projection rules for its bounds. It does not
open or capture at the member-access site.

### Descriptors

An anonymous existential carries a ZEP-0015 descriptor **only if `reified` is among its markers**:

```zeron
fn describe(box: Box<: Render + reified>): String { ... } // caller passes the hidden argument's descriptor
fn size(box: Box<: Render>): Int { ... }                  // erased; no descriptor, no type-bound test
```

A type parameter likewise carries a descriptor only if declared `reified`. The two forms have the
same cost model. The descriptor belongs to the hidden argument, not to the applied type
`Box<: ...>` itself: a `Box<: reified>` receiving `Box<Int>` carries the descriptor for `Int`.

Star views never carry descriptors.

### Packing and evidence

Packing happens implicitly where a concrete value meets an anonymous existential parameter. A
descriptor (if `reified`) and bound evidence are resolved at that site:

1. **Concrete type:** the hidden argument is known from the argument's static type; its descriptor
   is a constant or composed from reified variables in scope. Bound evidence uses ordinary witness
   resolution at the site, with the same imports and ambiguity diagnostics. Missing evidence is an
   error there; there is no runtime search.
2. **Type variable in scope** with the needed bound or `reified` marker: its descriptor and
   evidence are forwarded under the existing witness rules.
3. **Another anonymous existential:** what it was captured with is forwarded under the same
   entailment. An erased anonymous existential has no descriptor to forward, so it cannot be
   passed where `reified` is required.
4. **Capture time:** evidence is fixed when the call or declaration binding happens; later witness
   availability cannot rebind it.
5. **Static markers** (`nullable`, `mut`) are checked at the site and carry no evidence.
6. **Several bounds** resolve independently, and a failure names the missing bound.

The hidden type's runtime parts are separate from the bound witnesses:

```text
anonymous-existential argument
├── erased payload
├── hidden-argument descriptor        (only if reified)
└── bound evidence / witnesses        (only if a bound needs it)
```

Parameter-position anonymous existentials need no heap holder in this slice: descriptors and
evidence travel as hidden parameters.

Star views do not pack through this path. `Box<Int>` is accepted where `Box<*>` is expected by the
ordinary `out Any?` projection rule, with no descriptor or evidence.

### Capture and escape

An anonymous existential is bound at its declaration site. Inside the declaration it behaves as a
rigid unknown type; at generic calls the callee's type parameter is inferred to that bound variable
and forwards its descriptor and evidence. This is the rank-1 equivalence stated in the revision
note:

```zeron
fn swapFirstTwo(items: MutableList<: Any>) = swapImpl(items);
fn swapImpl<T>(items: MutableList<T>) {
    let a: T = items[0];
    items[0] = items[1];
    items[1] = a;
}
```

There is no separate per-call capture for the anonymous existential: the hidden variable is
established when the declaring callable is checked. For a binding supplied by a caller, the fresh
variable is the callee's hidden capture parameter.

**Escape rule:** no type mentioning an anonymous existential's hidden variable may appear outside
its declaration, whether in the result type, an outer binding, a raised effect, or a type that
outlives the declaration. A violation is an error that names the anonymous existential position.
Approximating an escaping hidden variable by its bound (as Java does) is a candidate extension for
ZEP-0105, because it would put existential types in local bindings and results.

A multi-statement computation over an anonymous existential is written as a generic helper
function, as above. [ZEP-0109](./ZEP-0109.md) makes the same thing expressible with a polymorphic
lambda.

Star views use the existing projection capture rules from ZEP-0052. This proposal adds no new
capture or escape rule for `F<*>`; any refinement of projection capture belongs to ZEP-0105.

### Skolemized `let` and opening

This slice does not introduce a source-level `let` that names an existential or introduces a
skolemized type variable. A local binding whose initializer is `F<*>` keeps the projection type;
it does not open the hidden argument.

Opening an anonymous existential across statements belongs to [ZEP-0105](./ZEP-0105.md)'s
pattern-scoped opening form, `if (box is Box<let T>)`. That form needs no rank-2 `use`; `use`
remains a library alternative for combinators. A general source-level skolemized `let` remains out
of scope. A reified existential stored in a binding is also subject to the holder ABI of
[ZEP-0106](./ZEP-0106.md). A `let`-bound polymorphic lambda scheme with skolemized expected
binders remains [ZEP-0003](./ZEP-0003.md) and [ZEP-0109](./ZEP-0109.md), not this proposal.

### Type-bound tests

A type-bound test is an exact runtime test against a closed applied type. It is available on a
`reified` type parameter and on a `reified` anonymous existential:

```zeron
fn render<T: Render + reified>(value: T): String {
    if (value is Box<Int>) {
        return renderInt(value);
    }
    if (value is Box<String>) {
        return renderString(value);
    }
    return value.render();
}

fn describe(box: Box<: Render + reified>): String {
    if (box is Box<Int>)    return "boxed int " + box.get();
    if (box is Box<String>) return "boxed string";
    return "other";
}
```

The test requires a descriptor for the tested type and for the value's static type or hidden
argument. A closed type uses a constant descriptor. A type mentioning a `reified` variable composes
its descriptor at runtime. On success, the compiler emits the existing cast and permits the existing
flow refinement; on failure, the branch is not taken.

A star view (`F<*>`) has no descriptor and supports no exact test. A value whose static type is just
a contract (`p: Render`) likewise has no descriptor. Contract-bound tests belong to
[ZEP-0108](./ZEP-0108.md); subtype matching of non-effect types has no owning proposal yet.

First-version matching rules:

- exact structural equality only;
- closed concrete applied types and types composed from reified variables;
- arrays represented recursively;
- nullability and mutability must match exactly;
- the target must be a closed type or mention only reified variables; a target containing `*`,
  `<: ...>`, or an unresolved variable is rejected;
- class patterns may then destructure the matched value using existing pattern rules;
- no subtype, interface, ancestor, or contract-bound tests.

The final pattern grammar is intentionally left to the prototype. It may reuse the existing
`is`/class-pattern surface or add applied type arguments to class patterns; it must not introduce a
second, incompatible notion of runtime type test.

### Evidence is not tested

A successful type-bound test does not imply that the value satisfies any additional contract. Bound
operations remain available through the captured evidence. Testing whether a hidden type satisfies
a contract is [ZEP-0108](./ZEP-0108.md), not this proposal.

### Variance

A star view is a covariant read-only projection. It is not interchangeable with a concrete
application in the reverse direction.

An anonymous existential hides an invariant argument. `Box<: B>` is not interchangeable with
`Box<Int>` or `Box<String>`; a `Box<Int>` is accepted where `Box<: B>` is expected by packing. This
slice does not introduce subtyping between anonymous existential types beyond that.

### Library index

Public signatures may contain star views and anonymous existentials, and `reified` markers on
anonymous existentials and type parameters. The index will record:

- star views as ordinary `out Any?` projections, since they are source sugar;
- anonymous existential positions with marker and bound order;
- the `reified` markers supplied by ZEP-0015.

This must share one schema revision with ZEP-0015, ZEP-0005 and [ZEP-0109](./ZEP-0109.md).
Consumers on older compilers reject newer indexes by schema version.

## Compatibility and impact

This is an additive source feature. It affects parsing and type formatting (`*` and `<:` in
type-argument position), the type system's packing and capture rules, runtime type tests, library
metadata, and diagnostics. Existing programs without these forms are unaffected. `?` in
type-argument position is not introduced; postfix `?` keeps its current nullable meaning.

The runtime cost is bounded in this slice: descriptors and evidence are hidden parameters, paid
only for `reified` markers and bounds that need evidence, and no holder is allocated. Monomorphic
type tests use constant descriptors. Star views add no runtime data.

## Alternatives

- **Later `?` wildcard** — rejected because `?` is already the postfix nullability marker and
  `Box<?>` next to `Box<Int?>` is a readability hazard. `*` is the Kotlin-familiar star form.
- **`F<* : B>`** — rejected because it recreates the bounded-wildcard ambiguity. Bounded
  existentials use the distinct `<: ...>` form.
- **Only `F<out Any?>` with no star sugar** — viable and semantically identical, but verbose for a
  common parameter shape. The canonical form remains available.
- **Named binder in type position (`<let T: B> T`)** — the 2026-11-09 design. Rejected: in
  parameter position it is equivalent to a rank-1 universal, adds a second place for the bound
  grammar, hides different semantics behind a similar spelling, and requires a per-expression
  capture and escape rule for a capability ordinary generics already have.
- **Binder in the type-parameter list (`fn f<let T: B>(p: T)`)** — marks `T` as callee-chosen and
  extends naturally to result positions. Deferred to ZEP-0105, where result positions create the
  need.
- **`any Contract`** — redundant in Zeron: contract → conformant subtyping already makes the
  contract itself a type for a whole value. Its real uses (storing, returning) belong to ZEP-0105
  and ZEP-0106.
- **Keep the full existential exploration** — too broad for a 0.7.0 slice.
- **Reification without existentials** — supports `reified` type-variable tests but leaves bounded
  unknown arguments unexpressible without declaring unused type parameters.
- **Erased tests only** — simple but cannot distinguish `Box<Int>` from `Box<String>`.
- **Contract-bound tests first** — requires runtime evidence selection and does not provide type
  identity; separated into ZEP-0108.
- **Stored existentials first** — adds holder ABI before the matching semantics are proven;
  separated into ZEP-0106.

## Implementation and validation

1. Parse and format `*` and `<: bounds + markers>` in type-argument position.
2. Resolve `F<*>` to the existing `F<out Any?>` projection and reject `Array<*>`.
3. Validate anonymous existential positions and markers; reject lambdas, function types, results,
   fields, variables, nested arguments, receivers, and arrays.
4. Implement implicit packing, descriptor and evidence forwarding, and the escape rule for
   anonymous existentials. A practical lowering is a hidden capture type parameter per
   existential, with the source signature retaining the `<: ...>` form.
5. Attach ZEP-0015 descriptors to `reified` anonymous existentials and type parameters.
6. Lower exact type-bound tests to descriptor comparison, cast, and existing flow refinement.
7. Extend the library index for anonymous existentials; encode star views as projections.
8. Test monomorphic and open tests, nullable/mutable distinctions, arrays, nested generic targets,
   separately compiled libraries, missing evidence, `reified` mismatches, escape errors, star
   assignment, and rejection of `Array<*>` and lambda existentials.
9. Measure descriptor allocation and test cost; cache monomorphic descriptors.

## Resolved implementation questions (2026-11-10)

- **Applied-type matching syntax:** reuse `is` with applied type arguments for boolean exact tests.
  Existing class and `match` patterns remain the destructuring mechanism; no new pattern kind is
  introduced by this slice.
- **Primitive sources and targets:** allowed through the existing descriptor and boxing path. A
  reified primitive source carries its descriptor; ordinary primitive targets keep the existing
  runtime test and boxing rules. Nullability remains a separate descriptor bit.
- **Nullable and mutable distinctions:** use normal source spelling (`T?` and `&T`). Exact descriptor
  equality includes both distinctions; there is no pattern-only spelling.
- **Multiple bounds and member access:** a member is resolved from the bound contract that declares
  it. Duplicate or incompatible members from different bounds are an error; no synthetic
  intersection type is introduced.
- **Escape:** an escaping hidden variable is an error in this version. Inferred return types that
  would expose a hidden parameter are rejected. Approximation by a bound and general local
  skolemized escape analysis are deferred to ZEP-0105.
- **Capture representation:** sharing with projection member access uses the ZEP-0052
  `TypeProjectionDescriptor`/`CapturedTypeDescriptor` model rather than a second capture type.
- **Index encoding:** anonymous existentials lower to ordinary hidden type parameters after the
  explicit parameters. Their reserved name prefix marks them as non-explicit, bounds and `reified`
  round-trip through the existing type-parameter encoding, and star views remain ordinary `out
  Any?` projections. No new index type code or schema version is required.
- **ZEP-0105 and ZEP-0109 boundary:** pattern-scoped opening (`value is C<let T>`) belongs to
  ZEP-0105 and is the primary local opening form. Rank-2 `use` remains a reusable library
  combinator from ZEP-0109; this slice does not depend on either.

## Resolved design questions

Carried over from 2026-11-09:

- **Scope split:** this proposal is the initial slice; general existential semantics move to
  ZEP-0105, storage to ZEP-0106, effect ancestry to ZEP-0107, and contract-bound tests to
  ZEP-0108. Subtype matching of non-effect types has no owner yet.
- **Runtime identity:** hidden arguments and reified variables use the shared ZEP-0015 descriptor.
- **Evidence:** contract witnesses remain separate from descriptors.
- **Packing:** implicit packing; no `pack` or `open`.
- **Version 1 positions:** anonymous existential parameter positions only.
- **Matching strength:** exact applied-type equality only.
- **Variance:** invariant for anonymous existentials; star views retain projection variance.
- **No binder in type position:** named types use ordinary type parameters.
- **Descriptors opt-in:** only `reified` anonymous existentials and type parameters carry them.

Added by the 2026-11-10 revision:

- **No type-argument `?`:** `?` is nullability only. `F<*>` is the unbounded read-only view.
- **Star equality:** `F<*>` is exactly `F<out Any?>` and carries no descriptor or evidence.
- **Anonymous existential spelling:** `F<: B + C + markers>` is the only bounded hidden-argument
  form. `F<: reified>` is the unbounded reified form.
- **No `? : Contract`:** bounded views use `F<out B>`; bounded existential binders use
  `F<: B>`.
- **`?` never implies `reified`:** reification requires `F<: reified>`.
- **Arrays:** `Array<*>` is rejected; arrays continue to reject projections.
- **Lambda boundary:** anonymous existentials in lambda and function-type parameters require
  ZEP-0109 and are rejected in this slice.
- **Skolemized `let`:** not in this slice; pattern-scoped opening belongs to ZEP-0105, with rank-2
  `use` from ZEP-0109 as a library alternative and reified storage in ZEP-0106. A general
  source-level skolemized `let` is not planned.

## Acceptance conditions (2026-11-10 revision approved)

The 2026-11-09 conditions apply except where changed by the approved 2026-11-10 revision. Items
marked ⟳ differ from the original accepted text.

1. ⟳ **Scope lock.** The release covers star views (`F<*>` as `F<out Any?>`), parameter-position
   anonymous existentials (`F<: bounds + markers>`), implicit packing, exact type-bound tests, and
   no storage. Named existential binders, result positions, scoped opening, variance, non-effect
   subtype matching, contract-bound tests, and lambda/function-type anonymous existentials require
   separate proposals.
2. **One type-test mechanism.** Unchanged: lowering through the existing type-test, cast, and
   flow-refinement machinery; no second runtime type-test system or general reflection.
3. **Descriptor dependency.** ZEP-0015 is accepted and implemented; this slice must use its
   descriptor ABI without changing exact identity or separate-compilation stability, and must
   demonstrate acceptable overhead for reified anonymous existentials. If it cannot, this slice
   does not ship in 0.7.0.
4. ⟳ **Evidence separation.** Bound witnesses remain separate from runtime type descriptors, and
   descriptors are carried only for `reified` markers. A successful type test does not imply a
   contract-bound test, and no runtime witness search is introduced. Star views carry neither.
5. ⟳ **Index coordination.** Anonymous existential signatures and markers must extend the versioned
   API index together with ZEP-0005's generic effects and ZEP-0109's quantified function types.
   Star views are encoded as existing `out Any?` projections. Older compilers reject newer indexes.
6. **Validation.** Unchanged in substance, plus `reified`/non-`reified` anonymous existential cases,
   star assignment and rejection of `Array<*>`, and rejection of anonymous existentials in
   lambda/function-type positions.
7. **Change control.** Unchanged. This revision is itself an application of this condition.

## Decision

The 2026-11-10 revision is approved. The accepted scope is star views (`F<*>` as `F<out Any?>`),
parameter-position anonymous existentials (`F<: bounds + markers>`), implicit packing, and exact
type-bound matching. The implementation follows the resolved questions above and remains a
`Candidate` for `0.7.0`, not a release commitment: ZEP-0015's descriptor ABI and the acceptance
conditions still gate the final release decision. The resolved questions are implementation
decisions within the accepted scope, not reasons to reopen the design direction.
