# ZEP-0114: Named Witness Declarations, Default Witnesses, and Explicit Witness Imports

## Abstract

Give witnesses stable names, normal visibility, and normal export/import behavior. Any witness,
named or anonymous, can be declared outside its contract or target package; the same-package orphan
rule is removed for every form. A named witness is activated with an explicit
`import witness package.Name;` instead of relying on package proximity. A `default` witness attaches
canonical evidence to a target type declared in the same source file and is activated together with
that type, mirroring how a class brings its same-named companion namespace. Coherence remains
unchanged: for a concrete target type and fully applied contract there must still be at most one
applicable witness in the active scope.

## Motivation

The current witness model is deliberately minimal, but its limitations now obstruct reusable
libraries:

- Witness declarations are effectively anonymous. The parser records the `witness` keyword as their
  name, the library index synthesizes `$zeron$witness$N` identifiers, and diagnostics cannot name a
  witness precisely.
- The orphan rule requires a witness to live in the package of its contract or target type. A
  library that owns neither cannot export a reusable witness, even when it is the natural owner of
  the implementation.
- Activation is package-based. A `package.*` import activates witnesses from that package, but
  there is no way to import one specific witness. The implementation also activates a witness when
  an explicitly imported type comes from the witness's package, which is broader than the
  documented rule and makes evidence depend on unrelated imports.
- Witness identity across separately compiled libraries is package-derived rather than a deliberate
  public name. Moving or renaming a witness package silently changes which consumers can use it.
- There is no way to mark the witness shipped beside a type as the canonical implementation for that
  type. Consumers must rely on package scope, and any eligible witness in the contract or target
  package competes with equal standing.

Naming and explicit imports address the first four problems. A name gives a witness an identity that
can be exported, imported, documented, and diagnosed, while leaving static selection and coherence
intact.

Anonymous declarations are deprecated at introduction rather than kept indefinitely: they are the
form that has no identity to export or import, so leaving them in place would preserve the
discoverability problem this proposal removes. They warn during the migration release and disappear
one release after the standard library migrates. The same-package orphan rule is removed at
introduction, independently of that deprecation.

A related problem appears one level below the package. A type author often declares the intended
witness in the same file as the target type, but package scope does not distinguish that witness
from an unrelated package's witness. Zeron already treats an imported class and its same-named
companion namespace as one import unit: importing the class makes `Class.member` resolvable
([ZEP-0072](./ZEP-0072.md)). A `default` witness extends that principle to canonical evidence. The
intended implementation travels with the type instead of depending on package-wide activation, and
the declaration is unique for that contract and target.

## Goals

- Add named witness declarations with the form `witness Name: Contract for Target { ... }`.
- Give witnesses normal visibility (`public` versus package-local) and export public witnesses under
  a stable qualified name.
- Add an explicit witness import form, `import witness package.Name;`, with optional aliasing and a
  witness-only wildcard form.
- Add `default` witnesses that must be declared in the target type's source file, are activated with
  the target type, and are unique for their contract/target pattern.
- Permit every witness declaration, named or anonymous, outside the contract and target packages;
  the same-package orphan rule is removed for all forms.
- Keep at-most-one-witness selection, overlap checks, and deterministic ambiguity diagnostics.
- Deprecate anonymous witness declarations at introduction, warn with replacement help during the
  migration release, and remove them one release after the standard library migrates.
- Keep `default` declarations beside their target type, because canonical evidence travels with
  the type; that is an ownership rule for defaults, not an orphan rule.
- Preserve witness evidence across separate compilation without changing runtime dispatch.

## Non-goals

- Making witnesses first-class values or allowing explicit evidence arguments at call sites.
- Changing witness member lookup priority or runtime method-handle dispatch.
- Changing overlap and coherence rules from [ZEP-0004](./ZEP-0004.md).
- Allowing user declarations to replace compiler-synthesized structural `Eq`/hash evidence for sums
  and products.
- General reflection, runtime witness search, or dynamic evidence selection.
- Importing witnesses through the ordinary type, function, value, or extension namespaces.
- Default witnesses on targets declared in another source file, another package, a compiled
  library, or a Java external class.
- Using `default` as a priority or override mechanism for competing witnesses. A default is
  canonical for its target's API but does not silently replace an explicitly active witness.
- Automatically converting every same-file witness into a default; adoption is explicit.
- Changing HKT contract semantics from [ZEP-0019](./ZEP-0019.md).
- Extending anonymous witness syntax beyond its removal release, or adding new forms of
  unnamed evidence declaration.

## Proposal

### Declaration syntax

A witness declaration may introduce a name before the contract:

```zeron
public witness BoxDisplay<T: Display>: Display for Box<T> {
    fn toString(): String = render(this);
}

public witness OptionMonad: Monad<Option<_>> for Option<_> {
    // methods
}

public delegating witness VectorNumeric<T: Numeric<T>>: Numeric<Vector2<T>> for Vector2<T> {
    // delegated methods
}
```

During the migration release the existing anonymous forms remain valid, but trigger a deprecation
warning and cannot be exported under a source name:

```zeron
witness<T: Display> Display for Buffer<T> { ... }
delegating witness Numeric<Vector2<T>> for Vector2<T> { ... }
```

After the `witness` keyword, an identifier is a witness name when a `:` follows it, either directly
or after a type-parameter list: `witness Name: Contract for Target` or
`witness Name<T>: Contract for Target`. Otherwise the identifier begins the contract type, exactly as
today. This keeps existing declarations source-compatible and avoids a new mandatory keyword.

`public` requires a name. An anonymous witness remains package-scoped during the migration release
and cannot be exported under a source name; once that release ends, anonymous declarations are
rejected with replacement help. `public delegating witness` is the visibility form for a delegating
witness.

Witness names occupy a separate declaration namespace, parallel to type, function, value, and
extension names. Duplicate witness names in one package are errors. A witness name may therefore
match a type or function name without a collision, and witness imports are unambiguous. Witness
names are never usable as expressions or type names, and they are not first-class evidence values.

A witness may be marked `default`:

```zeron
public class Box<T: mut> {
    public constructor new(value: T);
}

default witness<T: Display> Display for Box<T> {
    fn toString(): String = render(this);
}
```

A default witness is unnamed and is not written with `public`; its identity is the pair (contract
pattern, target pattern), and the compiler derives a hidden index key from that pair. Its visibility
follows the target type. It must be declared in the same compilation unit as the nominal declaration
at the head of its target type, or in the canonical owner package for an intrinsic target. That head
may be a class, sum, product, newtype, or supported intrinsic type. The target may be an applied or
nullable form whose head is declared in that file, but a nominal head cannot name a declaration from
another file, another package, a compiled library, or a Java external class.

`default` is an existing keyword used by contract default methods; this proposal reuses it in
witness declaration position rather than introducing a new keyword. `default delegating witness` is
the combined form for a delegating default witness; the existing `delegating witness` form remains
valid for ordinary witnesses.

In this document, an *ordinary witness* is any witness declaration that is not `default`, and an
*ordinary named witness* is an ordinary witness with a source name.

### Visibility and export

- A named witness without `public` is package-local.
- A `public` named witness is exported under its qualified name `package.Name`.
- A package-local witness is not exported and cannot be imported.
- A default witness has the visibility of its target type. It is exported when the target type is
  public and remains package-local otherwise. A default witness of a public target type must use a
  public contract. Default witnesses are never independently marked `public`.
- Anonymous witnesses keep their current runtime behavior during the migration release: they remain
  package-scoped, are exported with synthetic names, and are activated by the declaring package,
  including through a package star import. They are deprecated, and the next release rejects them.
- Compiler-derived witnesses remain synthetic. They are exported and activated with their declaring
  package so `derives` behavior is unchanged, and they cannot be named or explicitly imported by
  source code.

### Import and activation

A new import form activates witnesses without placing them in an ordinary declaration namespace:

```zeron
import witness acme.labels.IntLabel;
import witness acme.labels.*;
import witness acme.labels.IntLabel as LabelEvidence;
```

`acme.labels.IntLabel` is the qualified witness name. The alias defines the local witness name used
for diagnostics; it does not affect applicability or selection. `import witness pkg.*;` activates
all ordinary named public witnesses exported by `pkg` and imports no types, functions, values, or
extensions. Anonymous and compiler-derived exports have no source name and remain reachable only
through their declaring package's own scope or an ordinary `import pkg.*;`. Default witnesses are
not reachable through either witness-import form; they activate only with their target type.

`witness` is a reserved keyword, so the marker cannot collide with an ordinary import: a package
name cannot contain a `witness` segment, and `import witness.Foo;` is not a valid ordinary import.
The marker form always denotes a witness-only import and never imports types, functions, values, or
extensions.

The active witness scope is exactly:

1. all non-default witnesses declared in the current package, public or package-local;
2. all non-default witnesses exported by a package imported with `import pkg.*;`, including anonymous
   and compiler-derived exports with synthetic names;
3. all ordinary named public witnesses exported by a package imported with `import witness pkg.*;`;
4. exactly the ordinary named public witnesses listed by `import witness pkg.Name;` imports;
5. every default witness whose target type is an intrinsic type, or whose target type's nominal
   declaration is in scope through the current package, an explicit type import, or a package star
   import.

Apart from a target type's default witnesses, no import activates a witness. In particular, importing
a type, function, or value from a package does not activate that package's witnesses, and a default
witness is never activated by `import witness`. This removes the current implementation's implicit
type-import activation and makes evidence scope deliberate. The one explicit exception is a default
witness, whose activation is attached to its target type rather than to its package.

### Default witnesses

A `default` witness is canonical evidence attached to a target type declaration. It is declared in
the target type's source file and becomes active when the target type is in scope. This mirrors the
existing companion-namespace behavior: importing a class makes its same-named namespace members
reachable through the imported name ([ZEP-0072](./ZEP-0072.md)), and importing a class likewise
brings its default witnesses.

```zeron
public class Box<T: mut> { ... }

default witness<T: Display> Display for Box<T> {
    fn toString(): String = render(this);
}
```

Activation rules:

- The target's head nominal declaration is in scope when it is declared in the current package, is
  named by an explicit type import, or comes from a package star import. The same rules apply to
  classes, sums, products, newtypes, and intrinsic targets in their canonical packages.
- Importing the target under an alias still activates its default witnesses; an alias changes the
  source name, not the nominal target.
- A fully qualified type reference does not import the type and does not activate its default
  witnesses.
- Default witnesses cannot be named by `import witness`; an attempt is rejected and points to the
  target type import.

Canonicality and uniqueness:

- At most one default witness may apply to a fully applied contract/target pair.
- Two default patterns may not overlap, even when their target instantiations are textually
  different; the existing overlap checker decides overlap.
- A default witness is selected without a witness import, but it has no priority rule. If an
  ordinary witness is also active for the same pair, selection is ambiguous. The default does not
  silently win, because silent replacement would make evidence depend on import order or package
  layout.
- Within the target's own package, an ordinary witness that overlaps a default witness is rejected
  at declaration time because it could never be selected unambiguously.
- A default witness may be generic and may carry prerequisite bounds. Multiple non-overlapping
  defaults for distinct applied targets, such as `Box<Int>` and `Box<String>`, are allowed.
- A user-declared default may not overlap a compiler-derived witness for the same pair. Existing
  derivation restrictions, including the prohibition on user `Eq` witnesses for sums and products,
  continue to apply.

### Declaration placement

Declaration placement is unrestricted. A witness may be declared in any package, including one that
owns neither the contract nor the target type; there is no same-package requirement and no orphan
check for any declaration form. A named witness's visibility and import scope determine whether it
can be used, and an anonymous witness is activated through its declaring package:

- a package-local named witness is usable only inside its own package;
- a public named witness is usable wherever it is explicitly imported, or wherever its package is
  star-imported;
- an anonymous witness is usable wherever its declaring package is active, through that package's own
  scope or a package star import.

Defaults are the only placement-constrained declarations: a default must be declared in the target
type's file because canonical evidence travels with the type, and that rule expresses ownership of
the target, not the removed orphan rule.

This relaxation is intentional. A named witness has a stable identity, so a consumer can choose it
without relying on package proximity, while an anonymous witness stays reachable only through its
declaring package's activation, so placing one elsewhere does not widen its reach. Removing the
orphan rule does not remove overlap checking;
two witnesses for the same pattern in the same active scope remain an ambiguity.

### Coherence and selection

Applicability and selection are unchanged. For a concrete type and fully applied contract, the
compiler considers only active witnesses, applies generic prerequisites, and requires at most one
match. Missing evidence and ambiguity remain compile-time errors.

- Explicit witness imports have no priority over package-scoped witnesses.
- Selection does not prefer the current package, the nearest import, or the most recent import.
- Importing two applicable witnesses is an ambiguity even if one was imported by name and the other
  by a wildcard.
- A default witness is active through its target type rather than a witness import and has no
  priority over an ordinary witness. If both apply, the ambiguity names both candidates.
- Aliasing a witness changes only its local name, not its applicability.
- Overlap checks from [ZEP-0004](./ZEP-0004.md) continue to apply within the active scope, including
  between default and ordinary witnesses.
- A duplicate fully qualified witness name across loaded libraries is an error.

Ambiguity diagnostics should report the qualified names of the candidates. Missing-evidence
diagnostics may mention that a matching exported witness exists in a package that is not active,
but this hint is optional.

### Library metadata and separate compilation

`WitnessExport` already carries a qualified name and a target type. Named and default witnesses add
the following metadata:

- a public named witness uses its qualified source name, such as `acme.labels.IntLabel`;
- a default witness is unnamed in source and uses a generated reserved key beginning with
  `$zeron$default$`, derived from its contract and target, together with the default marker;
- an anonymous or compiler-derived witness keeps a reserved synthetic name beginning with
  `$zeron$witness$`, which cannot collide with a source identifier;
- a default witness carries a default marker; the existing `derived` flag continues to identify
  compiler-derived witnesses;
- a package-local witness, or a default witness whose target type is not public, is omitted from the
  index.

The loader implements default activation from that marker: a loaded default witness is active when
its target is intrinsic, or when the nominal declaration at the head of its target type is in scope,
without a witness import. The default marker must round-trip so consumers never infer default status
from a name convention.

Old indexes contain synthetic names, no default marker, and load as anonymous, package-activated
witnesses, preserving their current behavior. Consumers of a new index see named and default
witnesses and apply the new activation rules.

Because older consumers would otherwise treat every loaded witness as package-activated, a library
containing a named witness declared outside its contract and target packages, or a default witness,
must not be interpreted with the old
activation model. This feature changes the index schema, so bump `API_INDEX_SCHEMA_VERSION` once, or
otherwise raise the minimum supported consumer version, and coordinate that change with any other
pending index revision for the same release cycle. When the standard library adopts named public and
default witnesses, also bump `STANDARD_LIBRARY_API_VERSION`.

### Migration

1. Parse and represent named, public, default, and anonymous witnesses without changing existing
   syntax.
2. Enforce default placement in the target type's compilation unit, resolve the target head to a
   locally declared class, sum, product, or newtype, apply target visibility, reject overlapping
   defaults, and reject an ordinary witness declared in the target's own package that overlaps a
   default there.
3. Add the witness import channel to the import environment and resolve `import witness` forms.
4. Replace type-import-based activation with the explicit scope rules above. Add default activation
   through the target type's scope. Keep anonymous and derived witnesses package-activated during
   the migration window.
5. Export public named and default witnesses with their metadata, including the default marker, and
   omit package-local witnesses and defaults of non-public target types. Load old synthetic exports
   as anonymous witnesses.
6. Convert standard-library witnesses that are declared beside their target and are intended to be
   canonical to unnamed default declarations. Leave witnesses whose canonical status is still open as
   ordinary named witnesses. Packages such as `zeron.lang` and `zeron.io` remain implicitly
   star-imported.
7. Update documentation and diagnostics. Anonymous declarations warn with replacement help naming the
   replacement, and are rejected one release after the standard library migration completes. No
   orphan rule remains for any form.

Code that relied on importing a single type and thereby activating all witnesses from that package
must add `import witness pkg.*;` or `import pkg.*;`. Code that imports a package star keeps its
current activation. Explicit single-symbol imports no longer activate witnesses.

## Compatibility and impact

Named declarations, visibility, and witness imports are additive syntax. Existing anonymous
witnesses continue to parse and behave as they do today during the migration release, with a
deprecation warning; the following release removes the syntax. The same-package requirement is
removed for every form at introduction, so a witness that previously failed placement now declares
successfully. No new anonymous declaration is accepted once the warning ships.

The source-breaking change is the removal of implicit witness activation through explicit type
imports. This corrects behavior that already contradicts the documented rule in
[design-document-15](../design_documents/design-document-15_type-class-witnesses-and-generic-bounds.md),
but code may depend on it. Migration is usually a one-line witness or package star import.
Removing the same-package requirement only accepts declarations that previously failed; no existing
valid declaration changes meaning.

Adding a public witness for a foreign type and contract to a star-imported package can introduce a
new ambiguity for existing consumers. This is the intended consequence of normal package exports and must be called
out in release notes. Explicit witness imports give consumers a narrower alternative.

Default witnesses change what a type import activates. Importing a class now also activates the
canonical evidence declared beside it. This is additive for types without defaults, but a consumer
that also imports an ordinary witness for the same contract and target will now see an ambiguity.
The default does not override the ordinary witness. Type authors should declare a default only when
they intend it to be the canonical implementation, because the canonical witness is active whenever
the target type is imported; a consumer cannot shadow it with a competing witness while keeping an
ordinary import of the target type.

Witness selection remains compile-time and evidence remains hidden `MethodHandle` values. No
runtime dictionary or dynamic lookup is introduced. Existing witness helper methods and invocation
descriptors should remain valid; names used for diagnostics and metadata may change.

The library index requires a schema-version decision as described above. Old libraries remain
loadable, but newly placed named witnesses and default witnesses require a consumer that understands
the new activation rules. Standard-library index invalidation follows the usual versioning rules.

## Alternatives

- Keep anonymous witnesses and the orphan rule — smallest change, but blocks third-party reusable
  witnesses and leaves no explicit way to import one selected witness.
- Keep the orphan rule and add names only — improves diagnostics, but does not let a library own a
  witness for a foreign type and contract pair.
- Attach default witnesses to the package instead of the target declaration — preserves the status
  quo, but cannot guarantee same-file ownership or uniqueness and makes canonicality depend on
  package scope.
- Require `import witness` for a default witness — explicit, but defeats travel-with-the-type and
  makes importing the class insufficient.
- Treat `default` as a priority override — tempting, but selection would then depend on import order
  and package layout, and a local witness could silently replace the type author's canonical
  evidence.
- Use a pseudo-package for witnesses, such as `witnesses.acme.labels.IntLabel` — avoids the new
  import keyword, but invents a second package hierarchy and does not match ordinary exports.
- Put witness names in the ordinary declaration namespace — simpler name lookup for declarations,
  but forces witness names to compete with types and functions even though witnesses are never used
  as values.
- Allow `import pkg.Name` to import both a declaration and a witness of that name — compact, but
  makes witness activation an accidental side effect of an ordinary import, which is the problem
  this proposal removes.
- Make witnesses first-class values with explicit evidence arguments — more expressive, but a much
  larger change to inference, ABI, and call syntax.

## Implementation and validation

1. Extend the parser and AST with an optional witness name, `public` and `default` modifiers, and the
   existing anonymous/derived distinction. Support `public delegating witness` and
   `default delegating witness`.
2. Register witness names in their own package namespace, reject duplicates and reserved `$`
   identifiers, and accept witness declarations in any package with no orphan check. Enforce default
   placement in the target type's compilation unit, target-head resolution, uniqueness, and overlap.
3. Add witness imports to `ImportEnvironment` and `ImportResolver`; parse `import witness pkg.Name`,
   aliases, and `import witness pkg.*`.
4. Update witness activation: remove the current type-import activation clause, include visibility
   in the active-scope check, and activate default witnesses through the scope of their target
   type. Reject explicit witness imports of default witnesses.
5. Update `WitnessExport` encoding and loading: named public witnesses use `package.Name`, default
   witnesses carry a default marker, package-local witnesses and defaults of non-public targets are
   omitted, and synthetic names remain reserved. Bump the index schema as described above.
6. Convert standard-library witnesses that are declared beside their target and are intended to be
   canonical to default declarations, and update any imports that depended on explicit type imports.
7. Improve ambiguity and missing-evidence diagnostics to use qualified witness names, to identify
   defaults, and to emit the anonymous deprecation warning with replacement help naming the form.
8. Test named, anonymous, and default declarations; visibility; third-package declarations for
   foreign targets, named and anonymous;
   same-file default acceptance and cross-file rejection; activation through explicit, aliased, and
   star type imports; rejection of fully qualified and `import witness` activation for defaults;
   uniqueness and overlap; ambiguity between defaults and ordinary witnesses; generic and specialized
   defaults; class, sum, product, and newtype targets; derived and delegating witnesses; HKT
   witnesses; do-notation from [ZEP-0111](./ZEP-0111.md); a user package that reaches a
   standard-library witness through an erased or star bound, from both bundled sources and a compiled
   index; and separate-compilation round trips.
9. Test that an old index containing synthetic witness names still loads and behaves as before.
10. Remove `dist/` before compiling Zeron sources, run focused tests during development, and run the
    full `mvn test` suite sparingly.

## Settled design decisions (2026-11-11)

- **Parallel namespace.** Witness names live in their own package namespace, parallel to types,
  functions, values, and extensions. A witness is never a value or a type, so a witness name may
  match a type or function name, and `import witness pkg.Name` is never ambiguous with an ordinary
  import.
- **Both star forms exist.** `import pkg.*;` keeps activating every witness exported by the package,
  including anonymous and derived exports. `import witness pkg.*;` is the narrow form: it activates
  only named public witnesses and imports no types, functions, values, or extensions.
- **Aliases are diagnostic labels.** `import witness pkg.Name as Alias;` changes only the local name
  used in diagnostics. An alias never affects applicability, selection, or coherence, and future
  explicit evidence-selection syntax is not promised to reuse it.
- **Anonymous witnesses are deprecated at introduction.** Named and default declarations ship first;
  anonymous declarations keep working with a deprecation warning and replacement help during the migration
  release, and no new anonymous declaration is accepted once that warning ships. They are removed
  one release after the standard library completes its migration. Class-scoped `implementation`
  blocks and their `delegating` form are not anonymous witnesses and are unaffected.
- **Declaration placement is unrestricted.** Any witness, named or anonymous, may be declared in any
  package, including one that owns neither the contract nor the target type; the same-package orphan
  rule is removed at introduction for every form rather than kept for anonymous witnesses during
  migration. Only `default` stays beside its target type, because canonical evidence travels with
  the target, and that is an ownership rule for defaults, not an orphan rule.
- **A default witness is unnamed.** Its identity is the contract/target pair; the compiler derives a
  hidden index key and uses a readable `default Contract for Target` label in diagnostics and member
  discovery. `default` is never combined with `public`; visibility follows the target type.
- **A fully qualified type reference does not activate default witnesses.** Activation follows scope
  only: the current package, an explicit type import, or a package star import. Spelling
  `pkg.Type` does not import it, so spelling cannot change which evidence is available.
- **Overlapping defaults are declaration errors, not a precedence ladder.** A specialized default
  and a generic default may not overlap, because "most specific wins" would reintroduce
  order-dependent selection that ZEP-0004 deliberately avoids. Use bounds on the generic default, or
  an explicitly imported ordinary witness, when a more specific implementation is needed.
- **Defaults appear in member discovery and documentation as canonical evidence.** They are part of
  the target type's public API, grouped as evidence attached to the type rather than as members, and
  they are never presented as directly callable.
- **The index schema change ships with named and default witnesses.** Do not bundle unrelated
  metadata changes, but do not defer the default marker: it must round-trip, or loaded witnesses
  silently fall back to package activation. Bump `STANDARD_LIBRARY_API_VERSION` when the standard
  library adopts named and default declarations.

## Implementation status (2026-11-11)

Implemented in this slice:

- Named, `public`, unnamed `default`, and combined `delegating` witness syntax, including witness
  type parameters before `:` and anonymous compatibility. A default cannot declare a source name.
- Witness names in a separate package namespace, with duplicate-name diagnostics; source names are
  never resolved as types or values.
- Unrestricted declaration placement. The same-package orphan rule is removed for every form.
  `default` placement is checked against the target head's compilation unit, or against the
  canonical owner package for an intrinsic target.
- `import witness pkg.Name;`, aliased imports, and `import witness pkg.*;` parsing, duplicate
  detection, and validation: the import must name a public, named, non-default witness, or a
  package that declares witnesses.
- Activation follows the accepted scope rules: current package, ordinary package star imports,
  explicit named witness imports, witness star imports, and default activation through the target
  type's own scope. Explicit type imports no longer activate non-default witnesses, and a fully
  qualified type reference does not activate defaults.
- Class-scoped `implementation` blocks activate with their owner type. Importing the owner class,
  explicitly or through a package star import, activates the compiler-derived HKT witness; a
  package star import remains sufficient but is no longer required.
- `WitnessExport` carries the source name and default marker. Public named witnesses round-trip under
  `package.Name`; default witnesses round-trip under a generated `$zeron$default$` key with the
  default marker; package-local witnesses and defaults of non-public targets are omitted from the
  index; old synthetic names still load as anonymous witnesses. Schema 13 encodes the default marker.
- Existing overlap and ambiguity checks apply unchanged to the new forms, so overlapping defaults
  and an ordinary witness overlapping a default in the same active scope are rejected.
- Canonical standard-library defaults are unnamed `default` declarations beside their target types,
  or in the canonical package for an intrinsic target. `Int`/`Long` have default `Integral`
  evidence, and `Float` has default `Floating` evidence. All intrinsic targets are canonically owned
  by `zeron.lang`; `Array<_>` is no exception, but its `Foldable` evidence remains the named public
  witness `zeron.collections.ArrayFoldable`, imported explicitly, rather than a universally active
  default. The standard-library API version is 13.
- A default witness for a public target must use a public contract.
- Member discovery reports default witnesses and class-scoped implementation evidence as evidence
  attached to the target type, separately from callable members, for both source and compiled
  libraries.
- The anonymous-witness deprecation warning carries a replacement help naming the named form.

Deferred, without changing the accepted design:

- An automatic code action that rewrites an anonymous declaration. The warning now names the
  replacement form.

## Decision

Accepted 2026-11-11 with the resolutions above. Named witnesses get stable public identities,
normal visibility, explicit witness imports, and canonical `default` evidence declared beside the
target type. Declaration placement is unrestricted for every witness form; the same-package orphan
rule is removed at introduction, and only `default` stays beside its target type.
Anonymous witnesses are deprecated at introduction, warn with replacement help during the migration
release, and are removed one release after the standard library finishes migrating; class-scoped
`implementation` blocks are unaffected. The index gains named exports and a default marker under
the existing one-bump-per-release-cycle rule.

The proposal is implemented and unscheduled; the tracker records it as `Implemented` with no release
target.
