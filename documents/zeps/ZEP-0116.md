## Abstract

This proposal settles the work deferred from [ZEP-0105](./ZEP-0105.md) after its direct
`if`/`while` opening slice shipped. Its accepted scope is deliberately narrow:

- mixed exact/open patterns;
- nested opening when every level is statically known or raw-class testable;
- opening in an `else if` branch and in the true branch of a value-producing `if`;
- complete escape rejection for every path that would outlive the branch;
- shared capture representation with ZEP-0052 projections.

The following remain outside the accepted design: binder-declared bounds and markers,
`C<in B>` opening, result-position anonymous existentials, escape approximation or re-packing,
and variance or pointwise subtyping for existential views.

The implemented `C<let T>` form remains specified by ZEP-0105. This proposal does not reopen that
slice.

**Implementation status (2026-11-13).** Mixed exact/open patterns, nested opening, the `else if`
and value-producing `if` placements, and branch escape rejection for returns, assignments, and
raised-effect types are implemented. The implementation adds no runtime or API-index ABI. Binder-declared bounds, `C<in B>` opening,
result-position existentials, escape approximation, and variance changes remain rejected or
unsupported.

## Motivation

ZEP-0105 gives a local name to an otherwise hidden type argument:

```zeron
if (box is Box<let T>) {
    let value: T = box.value;
}
```

That covers the common branch-local case, but several useful cases still fail:

- a pattern that mixes a known argument with an opened one, such as `Map<Int, let V>`;
- a nested pattern such as `Box<Box<let T>>`;
- opening in an `else if` branch or in a value-producing `if`;
- proving that every escape path out of a branch is closed.

Without a defined continuation, users must fall back to hand-written helpers or unsafe casts. This
proposal is the design home for those continuations and fixes the boundary at branch-local
opening.

## Goals

- Define mixed and nested opening patterns without weakening ZEP-0105's branch scoping.
- Define the accepted `else if` and value-producing `if` placements.
- Complete escape rejection for raised effects, closures, fields, containers, and aliases.
- Specify how raw `Any` tests interact with class-declared bounds and available evidence.
- Share the capture representation with ZEP-0052 projections.
- Add validation for branch-local closures, exact tests, and every remaining rejection.

## Non-goals

- Re-specifying the implemented direct `if`/`while` opening form; see [ZEP-0105](./ZEP-0105.md).
- Stored existentials and holder ABI; see [ZEP-0106](./ZEP-0106.md).
- Rank-2 polymorphism and library `use`; see [ZEP-0109](./ZEP-0109.md).
- Contract-bound runtime tests; see [ZEP-0108](./ZEP-0108.md).
- Binder-declared bounds, `nullable`, or `mut` markers.
- Opening `C<in B>` or introducing lower bounds.
- Result-position anonymous existentials.
- Escape approximation by an upper bound or explicit re-packing.
- Variance or pointwise subtyping for existential views.
- General skolemized `let` in arbitrary type position.
- Reflection or dynamic type extraction from a descriptor.
- An `any Contract` type.

## Proposal

### Composed and conditional forms

ZEP-0105's direct `if`/`while` condition form remains available for mixed and nested patterns. The
additional placements accepted here are:

- an opening test in an `else if` chain;
- an opening test in the true branch of a value-producing `if` expression.

In both cases the binder is scoped to the true branch only. It is not visible in the condition, in
a following `else`, or after the `if` expression. A negated opening test never introduces a
binder.

Opening as one clause of `and`/`or`, and opening guarded by a preceding null or class check, are
rejected in this version. A short-circuit expression cannot make a binder available to the
remainder of the condition, so accepting those forms would require a separate flow-sensitive
typing rule. Users can split the condition into nested `if` statements instead.

### Mixed exact/open patterns

A mixed pattern such as:

```zeron
if (pair is Pair<Int, let V>) {
    let value: V = pair.second;
}
```

combines an exact argument test with an open binder. Mixed patterns are accepted with these rules:

- every exact argument must be statically justified by the source applied identity or by an exact
  descriptor that is already required by the pattern;
- mixed patterns do not invent a runtime descriptor for an exact argument;
- if the exact argument cannot be justified, the whole pattern is rejected rather than silently
  reduced to a raw class test;
- on a failed exact test the pattern is false and the binder is not in scope;
- open arguments are allowed only in invariant positions. A covariant or projected parameter is
  rejected because its hidden argument is not represented by the same capture.

This reuses ZEP-0104's static-proof boundary and does not depend on ancestor-aware descriptors.

### Nested opening

A nested pattern such as:

```zeron
if (box is Box<Box<let T>>) {
    // T names the inner hidden argument
}
```

is accepted when every level is statically known or raw-class testable and every exact argument is
justified under the mixed-pattern rule. The rules are:

- each level is tested from the outside in;
- multiple levels may introduce binders, but each binder becomes visible only after its own level
  succeeds;
- a failure at any level makes the whole pattern false and leaves every nested binder out of scope;
- no binder is visible on the false path or in the remainder of the enclosing condition;
- a level that needs an unavailable descriptor rejects the pattern at compile time.

The implementation does not fall back to an inexact descriptor or a raw `Any` approximation for a
nested level.

### Binder-declared bounds and markers

Binder-declared bounds and markers are rejected permanently:

```zeron
if (box is Box<let T: Render>) { // rejected
    // ...
}
```

The source type is the only authority for inherited evidence. Opening cannot strengthen a bound,
intersect a new bound with the source, or add `nullable` or `mut` to a binder. The diagnostic must
say that the source does not carry the requested fact and must not synthesize evidence. This
preserves the ZEP-0105 rule that opening never invents a witness or descriptor.

### Complete escape checking

ZEP-0105 rejects returns and assignments to non-branch-local bindings. This proposal completes the
escape boundary, and every listed context remains an error:

- raised effects whose type mentions an opened binder;
- closures and function values that capture a binder and escape the branch;
- storing a binder-typed value in a field or outer container;
- assigning through a reference or alias to storage that outlives the branch;
- returning a value from a nested lambda that outlives the branch;
- loop bodies and `break`/`continue` paths that would leak a binder;
- separate-compilation or library boundaries that would serialize a binder.

The diagnostic identifies the binder, the escape path, and the branch that owns it. A branch-local
closure that does not escape remains valid.

### No escape approximation or re-packing

Escape approximation and explicit re-packing are not accepted in this version. An escaping binder
is an error even when the value could be widened to its upper bound or wrapped in an anonymous
existential:

```zeron
fn leak(box: Box<*>): Box<*> {
    if (box is Box<let T>) {
        return box as Box<*>; // still an escape; rejected
    }
    return box;
}
```

Approximation would need a rule for preserving or discarding binder identity, and reified binders
would need a descriptor carrier coordinated with [ZEP-0106](./ZEP-0106.md). That work is left to a
future proposal rather than accepted implicitly here.

### Result-position anonymous existentials

Result-position anonymous existentials are not accepted:

```zeron
fn make(): Box<: Render>; // not supported by this proposal
```

Packing at the return site and opening at the call site would need a result-position ABI, and a
reified result would need the holder and descriptor-carrier work from
[ZEP-0106](./ZEP-0106.md). This proposal does not add that ABI. A future proposal must define the
carrier and the caller-side opening rules before this form is accepted.

### `in` projections and lower bounds

Opening `C<in B>` is rejected permanently. The type system has no lower-bound fact on an opened
binder, and this proposal does not add one. The rejection is a type-system boundary, not a
temporary implementation limitation. A lower-bound conversion would need its own subtyping rules
for combining lower and upper bounds.

### Variance and pointwise subtyping

Anonymous existentials hide an invariant argument in ZEP-0104. Star views are projections. Opening
does not change variance:

- `F<: B>` is not related to `G<: B>` by pointwise subtyping;
- covariant `F` does not preserve a wider bound through opening;
- an opened binder cannot be used where a covariant supertype is expected;
- projections remain a restricted existential view, not a general variance mechanism.

Pointwise subtyping remains deferred. A future proposal needs a concrete API and a sound treatment
of evidence before changing this rule.

### Raw `Any` and inherited class bounds

A raw test from `Any` proves only the erased class. Class-declaration bounds remain static type
facts, but opening does not synthesize the evidence needed to call bound operations. The rules are:

- a raw-class opening is accepted when the class needs no inherited evidence for the opened
  argument;
- when the class declares a bound whose evidence is unavailable, the pattern is rejected;
- the diagnostic distinguishes “bound known” from “evidence available”;
- opening never invents a witness or descriptor from a raw class test.

This applies equally to mixed and nested patterns.

### Shared capture and projection model

Pattern opening and ZEP-0052 projections share the same internal captured-type representation:

- star views approximate the hidden argument by `Any?`;
- anonymous existentials add implicit packing and capture at generic call sites;
- pattern opening introduces a branch-scoped rigid name for the already-captured argument;
- mixed and nested patterns preserve the same captured argument identities;
- descriptors and evidence are inherited, never synthesized by opening.

### Relationship to rank-2 and stored proposals

Rank-2 `use` remains a library alternative in [ZEP-0109](./ZEP-0109.md). Stored existentials remain
specified by [ZEP-0106](./ZEP-0106.md). Opening does not depend on rank-2 polymorphism, and it does
not move holder representation into the branch-scoped form. Result-position existentials are not
part of either accepted scope.

### Validation gaps

Focused coverage must include:

- branch-local closures that do and do not escape;
- raised effects that mention a binder;
- assignments through aliases, fields, and outer containers;
- mixed and nested patterns with exact, raw, and reified arguments;
- total and partial patterns at each nesting level;
- exact tests through the descriptors already required by the pattern;
- separately compiled library callers;
- rejected composed conditions, binder bounds, `in` opening, and result-position forms;
- the interaction of opening with `Codec`, `Encode`, and `Decode` bounds where applicable.

## Compatibility and impact

The accepted branch-local extensions preserve the ZEP-0105 ABI: no descriptor slot, evidence slot,
or library-index field is added for a binder that stays inside its branch. Mixed and nested
patterns reuse descriptors that the pattern already requires; they do not add a new wire record.

The source-compatibility impact is limited to previously rejected pattern shapes that now pass:
`else if` and value-producing `if` placements, mixed exact/open patterns, and nested opening.
Existing escapes stay rejected, result-position existentials stay rejected, and no accepted form
changes the holder representation from ZEP-0106.

## Alternatives

- **Keep every escape an error** — accepted. It is the simplest sound rule and keeps this proposal
  branch-local.
- **Approximate every escape by its upper bound** — rejected for this version because it loses
  binder identity and needs descriptor carriers for reified values.
- **Support only direct patterns permanently** — rejected because it leaves common map, container,
  and guard cases to hand-written helpers.
- **Reject mixed patterns permanently** — rejected because opening one argument while testing
  another is useful and can reuse the exact-descriptor boundary.
- **Add binder bounds later** — rejected. The source must remain the only authority for inherited
  evidence.
- **Add full variance immediately** — rejected as exceeding demonstrated need and complicating
  evidence.
- **Move result positions into ZEP-0106** — rejected for now; result-position ABI needs its own
  coordinated design rather than an implicit extension.

## Implementation and validation

1. Extended the parser and branch-scope machinery for `else if`, value-producing `if`, mixed, and
   nested opening.
2. Extended binder fact inference to preserve exact arguments and nested captures.
3. Implemented branch escape rejection for returns, assignments, and the raised-effect contexts
   listed above.
4. Added diagnostics that distinguish an unsupported shape, missing evidence, an unavailable
   descriptor, and a genuine escape.
5. Added positive and negative tests for every accepted extension and every remaining rejection.
6. Verified that no extension changes the ZEP-0105 branch-local ABI.

Implemented on 2026-11-13. Mixed and nested arguments are resolved recursively against the source
application; exact arguments must be statically justified, binders are limited to invariant
positions, raw `Any` openings cannot invent evidence, and raised effects plus return/assignment
paths reject escaping binder types. `OpeningPatternsTest` covers the accepted forms and the
remaining rejections. The accepted design still adds no runtime or API-index record.

## Settled decisions

| Decision | Outcome |
| --- | --- |
| `else if` and value-producing `if` | Accepted; binder scoped to the true branch only |
| `and`/`or` clauses and guarded openings | Rejected in this version |
| Mixed exact/open patterns | Accepted with statically justified exact arguments |
| Nested opening | Accepted when every level is statically known or raw-class testable |
| Multiple nested binders | Accepted; each visible only after its level succeeds |
| Binder-declared bounds and markers | Rejected permanently; source is the only authority |
| Escape contexts | Every escape is an error |
| Escape approximation and re-packing | Not supported in this version |
| Result-position anonymous existentials | Not supported in this version |
| `C<in B>` opening | Rejected permanently |
| Existential variance and pointwise subtyping | Invariance remains; pointwise subtyping deferred |
| Raw `Any` with unavailable evidence | Rejected with a targeted diagnostic |
| Shared capture model | Adopted with ZEP-0052 projections |
| Rank-2 `use` | Independent library alternative; opening does not depend on it |
