## Abstract

Add descriptive-statistics helpers to the existing `zeron.math` module: mean, median, variance, and
standard deviation over finite `Float` sequences, with explicit population and sample variants and
explicit handling of empty and single-element inputs.

## Motivation

`zeron.math` currently provides scalar helpers (`abs`, `min`, `max`, `clamp`) and the numeric
hierarchy supplies arithmetic, but there is no summary statistics. Users writing benchmarks,
telemetry summaries, or test reports either duplicate the same loops or pull in host libraries
through `unsafe`. A small standard surface also fixes the awkward cases: population versus sample
divisors, odd versus even medians, and empty input.

## Goals

- `Statistics.mean(values: Iterable<Float>): Option<Float>`.
- `Statistics.median(values: Iterable<Float>): Option<Float>`.
- `Statistics.variance(values: Iterable<Float>): Option<Float>` and
  `Statistics.sampleVariance(values: Iterable<Float>): Option<Float>`.
- `Statistics.standardDeviation(values: Iterable<Float>): Option<Float>` and
  `Statistics.sampleStandardDeviation(values: Iterable<Float>): Option<Float>`.
- Consistent `None` for an empty input and for a sample statistic with one element.

## Non-goals

- Streaming or one-pass accumulators; `0.9.0` offers whole-sequence helpers only.
- Weighted statistics, quantiles other than the median, regression, or hypothesis tests.
- Decimal or arbitrary-precision statistics. The helpers use `Float` and document their precision
  limits.
- Automatic conversion from `Int` or `Long` sequences. Callers map to `Float` explicitly.

## Proposal

```zeron
import zeron.math.Statistics;

fn main() {
    let samples = [1.0, 2.0, 3.0, 4.0];
    let mean = Statistics.mean(samples);                       // Some(2.5)
    let median = Statistics.median(samples);                   // Some(2.5)
    let spread = Statistics.standardDeviation(samples);        // Some(~1.118)
    let sample = Statistics.sampleStandardDeviation(samples);  // Some(~1.291)
}
```

- `mean` sums in `Float` and divides by the count. An empty input yields `None`.
- `median` collects the input into an `ArrayList`, sorts it with `sortedBy` and `Float`'s
  `Comparable<Float>` evidence (`compareTo`), and averages the two middle values for an even count.
  An empty input yields `None`.
- `variance` uses a two-pass algorithm: compute the mean, then sum squared deviations. This avoids
  the cancellation of the naive `E[x²] − E[x]²` form, and divides by `n`. `sampleVariance` uses the
  same two passes, divides by `n − 1`, and yields `None` when `n < 2`.
- `standardDeviation` and `sampleStandardDeviation` are the square root of the matching variance.

The language has no named arguments, so the sample and population variants are separate functions
rather than a boolean parameter. Callers cannot accidentally pass a bare `true` and get the other
definition.

## Compatibility and impact

- Additive functions in an existing standard-library package. No source break.
- Adds standard-library API-index entries, so `STANDARD_LIBRARY_API_VERSION` is bumped once in the
  release that includes them.
- No runtime representation, bytecode-shape, or intrinsic change.
- Documentation: extend the numeric and standard-library chapters with examples and the empty-input
  rules.

## Alternatives

- **Return `Float.NaN` for undefined results.** Rejected: it hides the empty and single-element
  cases and makes callers check for NaN, which is easy to forget.
- **A `Statistics` class holding a sample.** Rejected for `0.9.0`: a value type would imply
  incremental accumulation, which is out of scope.
- **Generic `Fractional<T>` signatures.** Rejected because integer division would silently produce
  integer means; `Float` keeps one obvious result type.

## Implementation and validation

1. Add a `Statistics` namespace to `src/main/resources/stdlib/zeron/math/math.zn` or a sibling file.
2. Reuse `Iterable`, `ArrayList`, and `sortedBy`; add no new collection machinery.
3. Test known sequences, including a constant sequence, negative values, an even and an odd count,
   one element, and the empty input.
4. Check `sample` variance against a hand-computed example and confirm the two-pass form does not
   lose precision on a large-mean sequence where the naive form would.

## Open questions

- Should `median` accept an overload for already-sorted input to avoid the extra copy on large
  sequences?
- Do we also want `mode` and `range`, or keep the surface to the four requested measures?
- Should the helpers live in a `Statistics` namespace or as extensions on `Iterable<Float>`?
