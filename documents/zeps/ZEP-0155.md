# ZEP-0155: Binary Buffers and Encodings

## Abstract

Add a `zeron.buffer` package for binary data: a growable `ByteBuffer` writer, a `ByteReader` cursor
over `Array<Byte>`, explicit endianness, fixed-width and variable-length integer encoding, bit
utilities, and hexadecimal and Base64 text codecs. Decoding failures are explicit typed values
rather than host exceptions.

## Motivation

Programs that read a binary format, implement a network frame, or write a fixture currently have
only `Array<Byte>` and manual shifts. There is no standard way to serialize an `Int`, no shared
endianness convention, and no checked hex or Base64 conversion. Each application reinvents the same
helpers with its own error behavior, and host `ByteBuffer` use leaks a host abstraction into
portable library code.

## Goals

- `ByteBuffer`: growable write-side buffer with `putByte`, `putBytes`, `putInt`, `putLong`,
  `putFloat`, `putBoolean`, `size`, `clear`, `toArray`, and an explicit byte order.
- `ByteReader`: cursor over `Array<Byte>` with position, remaining count, matching `get*` methods,
  and slice/remainder views.
- `ByteOrder` with `BigEndian` and `LittleEndian`; big-endian is the default.
- Unsigned LEB128 variable-length encoding for `Int` and `Long`, plus zigzag helpers for signed
  values.
- `Hex` and `Base64` encode/decode with strict, position-reporting failures.
- Bit helpers on `Int` and `Long`: population count, leading and trailing zeros, rotations, and bit
  reversal.

## Non-goals

- Direct or off-heap buffers, memory mapping, and zero-copy host views.
- Text encoding and decoding (`UTF-8`, `UTF-16`, `ASCII`). Those need their own proposal and
  malformed-input model.
- Compression, hashing, and encryption.
- Streaming readers over `InputStream`; `ByteReader` operates on one in-memory array.
- A binary format description language or schema-driven codec.

## Proposal

```zeron
import zeron.buffer.ByteBuffer;
import zeron.buffer.ByteOrder;
import zeron.buffer.ByteReader;
import zeron.buffer.VarInt;

fn main() {
    let mut writer = ByteBuffer.empty();
    writer.order = ByteOrder.LittleEndian;
    writer.putInt(300);
    writer.putVarInt(70000);

    let bytes = writer.toArray();
    let mut reader = ByteReader.over(bytes);
    reader.order = ByteOrder.LittleEndian;
    println(reader.getInt());  // Ok(300)
    println(reader.getVarInt()); // Ok(70000)
}
```

- `ByteBuffer` grows geometrically and never exposes its backing array. Encoding a value appends
  bytes at the current end; there is no read cursor. `size` is a byte count, not an element count.
- `ByteReader` holds a position and a byte order. Each `get*` returns `Result<T, BufferError>` and
  leaves the position unchanged on failure.
- `BufferError` is a closed sum: `Truncated(needed: Int, remaining: Int)`,
  `MalformedVarInt(offset: Int)`, and `InvalidText(offset: Int)`.
- Varints are LEB128 with a documented maximum encoded length and rejection of overlong or
  truncated forms. Zigzag encoding is exposed as explicit functions rather than an implicit mode, so
  a stream cannot silently mix signedness conventions.
- `Hex.encode(Array<Byte>): String` emits lowercase hexadecimal. `Hex.decode(String):
  Result<Array<Byte>, BufferError>` requires an even number of digits and rejects any other
  character with its offset.
- `Base64.encode(Array<Byte>): String` emits the standard alphabet with padding;
  `Base64.decode(String): Result<Array<Byte>, BufferError>` accepts the standard alphabet, optional
  padding, and rejects URL-safe characters unless a separate `decodeUrl` function is called.
- Bit helpers are public extension functions on `Int` and `Long` and have no effect row.

## Compatibility and impact

- Additive standard-library package. Existing programs are unaffected.
- Adds API-index entries and bumps `STANDARD_LIBRARY_API_VERSION` once in the release that includes
  the package.
- No intrinsic or runtime ABI change; the implementation uses `Array<Byte>` and existing operators.
- The package name `zeron.buffer` is settled here; `zeron.binary` was considered and rejected because
  the central type is a buffer and the text codecs are conversions of its contents.
- Documentation: a binary-data chapter with byte-order, error, and varint examples.

## Alternatives

- **Re-export `java.nio.ByteBuffer`.** Rejected: it is host-specific, mutable through views, and its
  position/limit/flip protocol is awkward to expose through Zeron references.
- **Separate packages for buffer and text codecs.** Rejected for `0.9.0`: the codecs operate on
  `Array<Byte>` and have no independent lifecycle.
- **Implicit endianness from the platform.** Rejected: formats and protocols need a fixed convention;
  silence here produces non-portable data.

## Implementation and validation

1. Implement `ByteBuffer` over `ArrayList<Byte>` or a raw `Array<Byte>` with a size field; keep the
   growth policy private.
2. Implement `ByteReader` with explicit bounds checks before any index access, so failures are
   typed and position-reporting.
3. Add `VarInt` with round-trip tests for `0`, `1`, `Int.max`, `Long.max`, and negative values
   through zigzag.
4. Add `Hex` and `Base64` with test vectors from the respective specifications and malformed-input
   tests for every rejection path.
5. Test bit helpers against known values, including `Int.min`, `Long.min`, and rotation by zero and
   by the full width.

## Open questions

- Should `ByteBuffer` expose a `capacity`/`reserve` pair, or keep only `size` and grow implicitly?
- Should `Base64` support URL-safe decoding through a mode parameter or a separate `decodeUrl`
  function?
- Is a shared `Buffer<T>` abstraction worthwhile, or is a byte-specific buffer enough for the
  standard library?

## Decision

Implemented 2026-11-24 and shipped in `0.9.0`. `zeron.buffer` provides `ByteOrder`,
`ByteBuffer`, checked `ByteReader`, `BufferError`, LEB128 `VarInt` helpers including zigzag,
pure-Zeron `Hex` and `Base64`, and `Int`/`Long` bit extensions. Scalar bit and float conversions
delegate to the runtime support class; encodings stay in Zeron so `Array<Byte>` keeps its runtime
representation.
