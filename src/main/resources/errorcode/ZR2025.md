# Error code ZR2025: Nullable type-parameter value requires a null check

A value whose type is a type parameter declared `T: nullable` may be null inside the generic body.
The declaration admits nullable type arguments such as `String?`, so the body cannot assume the
value is non-null when it reads a member, calls a bound operation, or passes the value where a
non-null type is required.

## Typical example

```zeron
fn describe<T: nullable>(value: T): String = value.toString();
```

`describe<String?>(null)` would fail at run time, because generic bodies erase `T` and no null
check is inserted.

## Suggested fix

Check the value against `null` before using it, let flow refinement prove it non-null, or use safe
navigation when a missing value should produce a nullable result.

```zeron
fn describe<T: nullable>(value: T): String {
    if (value == null) return "null";
    return value.toString();
}
```

Inside the refined region the bound's operations and `Any`'s members are available, and the value
may be passed to a parameter of type `T` or to `Any?`. Moving the value without using it, storing
it, comparing it with `null`, using `?.`, and the explicit assertion `!!` do not require a check.
