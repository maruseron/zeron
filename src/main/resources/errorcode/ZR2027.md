# Error code ZR2027: Direct Java access requires unsafe

Calling a Java method, constructor, or field directly bypasses Zeron's checked host boundary. Those
operations must be acknowledged with an `unsafe` expression. Curated `external class` and
`external fn` facades remain trusted and do not require `unsafe`.

## Typical example

```zeron
fn length(path: String): Long = java.nio.file.Path.of(path).toFile().length();
```

## Suggested fix

Wrap the direct host access in `unsafe`. The wrapper does not hide raised effects from the operand;
it only acknowledges direct Java access and lets checked Java exceptions escape without a mapping.

```zeron
fn length(path: String): Long = unsafe java.nio.file.Path.of(path).toFile().length();
```

Prefer an `external class` facade when the operation is part of the program's stable host boundary.
Public `static final` fields with a class-file `ConstantValue` are exempt, so constant reads do not
need `unsafe`.
